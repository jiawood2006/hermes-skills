## 二、差距分析（逐项，不做自我安慰）

### doc-ocr
| 能力 | 同类谁有 | 我们原来 | 判定 |
|:--|:--|:--|:--|
| 剔除页眉/页脚/水印 | Umi-OCR「忽略区域」 | ❌ 无 | **真缺口** |
| 生成可搜索 PDF | OCRmyPDF（它的立身之本） | ❌ 无 | **真缺口** |
| 指定识别语言 | PaddleOCR/EasyOCR 多语言 | ⚠️ 硬编码 zh+en | **真缺口** |
| 跨平台引擎 | 三者都跨平台 | ❌ 仅 macOS Vision | 缺口，**本轮未补**（见待办） |
| 二维码识别 | Umi-OCR | ❌ 无 | 缺口，低优先级 |
| 表格结构识别 | PaddleOCR PP-Structure | ⚠️ 靠 LLM 转 CSV | 够用，暂不动 |
| 版面阅读顺序 | Umi-OCR 排版解析 | ✅ 已有 bbox 重排 | 打平 |
| 批量容错 | — | ✅ 已有（坏文件不中断） | **我们更强** |
| 结构化字段抽取 | — | ✅ 已有（LLM 抽发票/合同/表格） | **我们独有** |

### video-to-text
| 能力 | 同类谁有 | 我们原来 | 判定 |
|:--|:--|:--|:--|
| 字幕文件（SRT/VTT） | stable-ts 等生态标配 | ❌ 只有文字稿 | **真缺口** |
| 词级时间戳按句切分 | stable-ts / whisperX | ❌ 无（一段可横跨十几秒） | **真缺口** |
| 简体中文 + 标点 | — | ❌ **输出繁体、无标点**（实测发现） | **真缺口（中文特有）** |
| 多语言转写 | 三者都支持 | ⚠️ 硬编码 zh | **真缺口** |
| 主页/批量下载 | jiji262 | ❌ 仅单条链接 | 缺口，本轮未补 |
| 去水印下载 | jiji262 | ❌ 无 | 缺口，本轮未补 |
| 硬字幕 OCR 提取 | video-subtitle-extractor | ❌ 无 | 缺口，本轮未补 |
| 多平台（快手/TikTok） | Evil0ctal | ⚠️ 仅抖音闭环 + B站元数据 | 缺口，本轮未补 |
| 口播内容情报 | — | ✅ LLM 摘要 + 爆款结构拆解 | **我们独有** |

> **判断**：video-to-text 的星数差距里，**一半是分发**（jiji262/Evil0ctal 是给全网的下载器，我们是 agent 技能），**一半是真功能**（字幕/切分/简体）。后者必须补——因为「转写出来只能读、不能拿去剪片」是硬伤。

## 三、本轮采纳项（已实现 + 实测）

### doc-ocr v2.0.0 → v2.1.0
| 新增 | 对标来源 | 实测证据 |
|:--|:--|:--|
| `--ignore-region "top=8%,bottom=6%"` 页眉页脚水印过滤 | Umi-OCR 忽略区域 | 造含页眉页脚的扫描件 → 运行时输出 `↳ 忽略区域剔除 2 块文字`，正文 6 行完整保留 ✅ |
| `--searchable-pdf` 扫描件 → 可搜索 PDF | OCRmyPDF 核心功能 | 纯图像 PDF → 写入 7 个隐形中文文字块；回读 `get_text()` 成功，`采购合同摘要`/`128`/`青岛泛合同创` 三项均可检索 ✅ |
| `--lang zh-Hans,en,ja...` 多语言 | PaddleOCR/EasyOCR | 参数生效，缺省 zh-Hans,en ✅ |

实现要点：复用 Vision 已有的 bbox 坐标做区域判定；可搜索 PDF 用 PyMuPDF 内置 CJK 字体（`china-s`）+ `render_mode=3`（隐形）写文字层，**原版面观感不变**。

### video-to-text v3.0.0 → v3.1.0
| 新增 | 对标来源 | 实测证据 |
|:--|:--|:--|
| `--subtitles srt,vtt` / `--format srt\|vtt` 字幕导出 | stable-ts 生态标配 | `say` 生成中文语音 → 端到端转写 → 产出 4 条 SRT，时间戳 `00:00:00,000 --> 00:00:02,760` ✅ |
| 词级时间戳 + 按句打包切分 | stable-ts / whisperX | 修前：1 条字幕横跨 13 秒；修后：4 条按句切分 ✅ |
| 简体中文 + 标点（`initial_prompt`） | 中文场景通病 | 修前 `為什麼意言就能看出來`（繁体无标点）→ 修后 `为什么一眼就能看出来。`（简体带标点）✅ |
| `--asr-lang` 多语言转写 | 同类通用 | 参数生效，中文额外注入简体引导 ✅ |

## 五、方法论复盘

1. **先分清"分发差距"还是"功能差距"**——第一轮（humanizer）是分发，本轮是功能。误判会导致努力方向全错。
2. **动手前先读自己的代码**：差点把已有的"版面还原/批量容错/结构化抽取"当成缺口，也差点重复实现已有能力。
3. **跑真实端到端才能发现真问题**：这轮最有价值的两个修复（**whisper 输出繁体无标点**、**字幕一条横跨十几秒**）**都不是对比 README 能看出来的**，是实际跑语音转写才暴露的。**对标 ≠ 只读文档，必须真的用一遍。**
4. **留下的"未采纳清单"要写明理由**——不是所有差距都该补，写清楚是"不做"还是"还没做"，下次复看才不会重复评估。
