## 一、规则

1. **每一个镜头都必须是 AI 生成的真运动视频。**
   静图 + `zoompan`/Ken Burns/位移 充镜头 = 用户判「贴图」。静图版虽然 0 元，但会被整片判废
   —— **省钱不能省在"画面是不是真动"上**。
2. **花字动画不算镜头运动。** PIL 逐帧叠字（`scripts/overlay_anim.py`：弹入、错峰淡入、渐变遮罩条、
   尺寸徽标）只是信息层；主体不动，用户照样判贴图。
3. **产品保真与"真运动"可以同时满足**：把官方实拍照片当 `first_frame` → AI 产出真运动，
   而产品就是官方真像素（尺寸/形态/logo 天然正确），人物也是真人（免 AI 磨皮脸）。
4. **交付前必须量化验运动**，肉眼"看着还行"不算验过：
   ```bash
   python3 scripts/verify_motion.py 成片.mp4
   ```
   - 冻结区间（freezedetect）**必须为 0**（硬指标）
   - 帧间差均值（tblend=difference + signalstats YAVG）作辅证，越小越"糊"
   - 15s v2 通过验收的实测值：冻结 0；帧间差 A 3.45 / B 2.59 / C 4.37 / D 1.57

## 二、15s 全运动版结构（v2 验收通过，可直接复用）

| 镜头 | 内容 | 时长 | 做法 |
|---|---|---|---|
| A | 官方真人实拍·剃须 | 2.7s | 首帧法 → `videoretalk` 口型对齐配音（0.08 元/秒） |
| B | 产品特写 | 4.9s | 首帧法（官方拉页图裁 9:16） |
| C | 真人手从内袋取产品 | 4.6s | 首帧法（拉页图-3）+ 尺寸徽标花字层 |
| D | 产品英雄（缓慢推进） | 2.8s | 首帧法（拉页图-12，自带 74mm/39mm 标注）+ ¥169 花字层 |

- 首帧字段：`media:[{"type":"first_frame","url":...}]`
  （可灵 `kling-v3-omni-video-generation` mode=pro = 1080P；万相3.0 `wan3.0-video`；均 1.2 元/秒）
- 镜头D 实测：**AI 缓慢推进时官方 74mm/39mm 标注线不变形** ✓
  → prompt 必须写「不要改变画面中已有的标注线与文字，只让背景光影轻微变化」。
- 配音：edge-tts 分段，每段 ≤5s（`--rate=+20%`），逐段实测时长再定镜头时长
  （实测 s1/s2/s3 = 2.64 / 4.78 / 4.58s）。
- 合成：concat → `adelay` 排时间轴 → `amix` → **必须加 `apad`**（否则与 `-shortest` 一起把成片截短，
  实测 15s 被截成 13.1s）→ `drawtext` 字幕（`enable='between(t\,0.3\,2.6)'` 逗号要转义）。
- 长命令别写成巨型一行（会被 hardline 拦）→ 落成 `.sh` 再 `bash` 跑。

## 三、素材纪律（顺手把尺寸问题一起解决）

- 客户官方拉页（`拉页图-*.jpg`）通常自带**真人 + 使用场景 + 尺寸标注**三件套，先翻官方物料再自己造图：
  - `拉页图-2` 商务男士侧脸剃须（真人肤质）→ 镜头A
  - `拉页图-3` 真人手从大衣内袋取产品（官方标注「鸡蛋大小 / 7cm / 70g」）→ 镜头C
  - `拉页图-12` 产品英雄图（自带 74mm×39mm 尺寸标注）→ 镜头D
- **避开官方文案**：只裁"人物+产品"完全无字的窗口。
  ❌ 不要用色块硬盖，也不要用"逐行取背景色向左延展"（实测产生横向涂抹条纹，比文字更糟）。
- 官方自带的尺寸标注**保留**——它正好是"尺寸真实"的视觉证据（用户在意尺寸）。
- 用户对失真的量化判据：真机 74×39mm（鸡蛋大小、握在手心约占手掌 2/3 宽）；
  成片里产品 ≈1.5~2 倍手掌宽 = **严重失真**必须回炉。让模型"画"产品它必然把主角放大
  —— 这是**流程问题，不是提示词问题**。
