# 投放指标与完播率 · 钩子变体批量跑（总纲）

> 合并自 3 篇（均 2026-09-18）：`retention-and-ad-metrics-optimization`、`ad-metrics-and-batch-testing`、`hook-variant-batch-run`。
> **什么时候读**：用户问「怎么提高完播率」「我们现在做的视频能达到效果吗」「素材能不能跑量」，或直接说「**跑 6 条看看**」时。
> **这篇管什么**：① 指标基准数字 ② 提高完播率的改法 ③ 批量素材淘汰打法 ④ 6 条钩子变体怎么批量跑 + 核验 + 交付。
> 口径铁律：**不许凭感觉答** —— 先给查证过的基准数字 → 再体检自己的成片 → 最后给可执行的测试设计；回复里要分清「哪些是基准数据、哪些是我的判断」。

## 一、指标基准（2026-09 查证，勿凭记忆编数字）
来源：91运营网《短视频完播率多少算及格》/ 蝉妈妈 / MCN 完播率拆解 / 快手行业数据。

| 指标 | 及格 | 优秀 | 爆款潜力 |
|---|---|---|---|
| 整体完播率 | > 15% | > 30%（播放量约为普通视频 3–5 倍） | > 40% |
| 3 秒完播率 | 40%–50%（视频号/抖音） | ≥ 60%（低于即须改开头） | — |

- **快手完播率最高的时长区间 = 10–15 秒**（平台默认 12 秒）；娱乐/生活类中位时长 14–16 秒，知识类约 30 秒。
- 观众 **0.3 秒**内决定是否划走；平台算法对完播率权重约 35%（有资料称 ≥35%）。
- ⚠️ **完播率高 ≠ 赚钱**：完播是**诊断指标**，最终看 **点击率 × 转化成本（ROI）**。为拉完播或为"干净/调性"牺牲转化（例如把结尾 CTA 一起删掉）是亏的。用户口径：**价格可以不出现（价格常变），但动作引导必须有**。

## 二、提高完播率的改法

### 15s 主力版结构（含 CTA、不含价格）
`0–5s 钩子 → 5–15s 正片 → 结尾 CTA「点下方小黄车」` ＋ 顶部花字 ＋ 参数条 ＋ 右下「AI 生成内容 · 广告」。
- **全片不出现价格**（用户铁律，价格常变）；但**动作引导必须有**。
- ❌ 已作废（2026-09-18）：15s 四段结构「0–3s 钩子 / 3–6s 产品登场 / 6–12s 一个使用场景 / 12–15s 收尾」→ 现：**0–5s 钩子 + 5–15s 正片**。
- 三种钩子各出一版做 A/B（话术照抄，别改写）：
  - 冲突型：「刮不干净？不是胡子的问题，是刀头」
  - 利益型：「出差 90 天，不用带充电线」
  - 悬念型：先给结果画面（剃完的脸 / 镜中前后对比）再揭产品

### 内容与节奏铁律
- **每 2–3 秒必须有画面变化或新信息**；删掉所有纯过渡镜头。
- 只讲**一个**核心差异（8500 转 *或* 70mm 迷你），别并列堆卖点。
- 使用场景**一个就够** —— 场景一多信息密度被摊平，观众第 2–3 个镜头就"猜到结局"划走。
- 设计阶段写全真实卖点，不因"没证据"删卖点（举证属投放阶段）；也不要拿"完播友好"当借口删卖点。

### 30s 主片的定位与结构
- 30s 主片 = **车内 10s + 镜前 10s + 水洗充电 10s**；旁白 edge-tts 云希 **`zh-CN-YunxiNeural`**，rate **`+5%`**。
- 时长基准不变：**要跑量仍以 15s 变体为准 —— 30 秒片在完播上天然吃亏**（最优区间 10–15 秒）。
- 定位：30s 作**主片**（+ 详情页素材）与 6 条 15s 变体一并交付；跑量决策看 15s 变体、**看 3 秒完播率**。
- ❌ 已作废（2026-09-18）：30s「6 镜并列生活情景 + 画外旁白、结尾只有参数条无 CTA」→ 现：**3 段 ×10s**（车内 / 镜前 / 水洗充电）。
- 旧诊断（HSQ1 v23 自查，教训仍有效）：30s 的翻车**不在制作而在结构** —— 时长是最优区间的 2 倍、前 3 秒是平铺叙事（人物起床 / 车内取物，无悬念、无冲突、无利益点）、中段信息密度平、结尾无 CTA（价格按要求删掉后没补动作引导）。

### 成片体检清单
1. 前 3 秒有没有：视觉冲击 / 悬念 / **利益点**？（只是"人物在做一件事"的平铺叙事 = 不合格）
2. 中段信息密度是否递增？场景是否超过 2 个？
3. 结尾有没有 CTA？
4. 要跑量的话时长是否 ≤ 15s？
5. 有没有拿"完播友好"当借口删卖点？
6. 把用户原话当验收标尺：他对"效果"的判据是 **产品是否真实 + 有没有生活情景**，不是画面唯美。

### 回答「我们现在做的能达到效果吗」的正确姿势
用户要的是**否定的专业判断 + 指出方向问题**，不是顺着说好话：
1. **结论先行**：「投出去完播率不会好；而且精修一条大片这个方向本身就不对」放第一句；
2. 再给**查证过的基准数字**（不允许凭记忆编）；
3. 给**逐项体检表**（项目/现状/判断）：时长 / 前 3 秒 / 中段 / 结尾 / 产品真实性，逐行标 ✅❌；
4. 明确区分目标：**「品宣片」 vs 「带货素材」**，按目标分别下判断；
5. 收尾给**更根本的方向性判断 + ≤2 个可执行选项**（含 A/B 方案与用真实投放数据决策的办法）让他拍板，不要停在建议。

## 三、批量素材淘汰打法（比精修单条重要）
- 磁力金牛 3.0 把 **「活跃素材数」+「潜力素材花费占比」** 放上首页核心指标 → 跑量杠杆 = **素材数量 × 快速淘汰**，不是单条质量。
- **1 条 30s 精修 = 1 个素材 = 1 次测试机会**；同样成本应出 **6 条 15s**（3 种钩子 × 2 个场景），投 3 天，看数据留 1–2 条。
- 结构：一条主干（产品锁真）+ 换多个「开头 5 秒」钩子段 → 批量产出。
- 出片成本参照：720P **0.6 元/秒**；一条 15s ≈ 9 元 → 6 条 ≈ 54 元可做一轮测试（走 §四 的省钱结构时只需 3 段的钱）。
- 意义：**出片必须便宜到可以批量**。
- ❌ 已作废（2026-09-18）：旧盘点「零件齐全（submit/fetch/核验/装配都有脚本），但缺一条命令出片的整机，待补 `make_ad.py`」→ 现：**整机已落地** `scripts/make_ad.py`（plan/submit/fetch/verify/assemble/deliver，见 SKILL.md）。
- ❌ 已作废（2026-09-18）：钩子/产品段走 `wan2.7-r2v`（`parameters.duration: 5` 实测可用，720P ≈3 元/段）→ 现：画面里有产品的段用 **`wan3.0-video`**（0.6 元/秒、免开通、支持 30s），`wan2.7-r2v` 只留不挑产品的镜头；5s 段成本仍 ≈3 元/段。

## 四、钩子变体批量跑法：6 条 = 3 种钩子 × 2 个场景（2026-09-18 实测：6 条一次跑通）
用户说「**跑 6 条看看**」= 按素材工厂打法做钩子 A/B。目标不是"再出一条大片"，而是**一次拿到 6 个可投放素材，用真实数据淘汰**。

### 1. 省钱的批量结构（关键）
| 部分 | 做法 | 成本 |
|---|---|---|
| **钩子段** | 3 段**新生成**（各 5s，钩子各不同） | 5s×0.6 元 = **3 元/段**，共 9 元 |
| **正片段** | **复用已通过核验的老素材**（各 10s，从既有 seg 取） | **0 元** |
| 装配/切条/交付 | `assemble,deliver` | **0 元** |

→ 6 条成片只花 3 段的钱。**同场景的两条差异只在开头 5 秒** = 变量唯一，投放后才能判断"是哪个钩子在起作用"（**这是有意的单变量对照设计，交付时要主动向用户说明**）。

### 2. 用 make_ad 跑（`assembly.order` 支持直接引用已有文件）
```python
"assembly": {
  "order": [
    {"file": "/tmp/r2v/hooks2_h1.mp4", "label": "钩子(冲突型)"},   # 新生成的 5s 钩子
    {"file": "/tmp/r2v/v12_v20_seg1.mp4", "trim": 10, "label": "车内"}  # 复用老素材
  ],
  "total": 15.0,
  "vo": {"file": "vo15_v1.mp3", "voice": "zh-CN-YunxiNeural", "rate": "+5%", "build": True},
  "subs": [
    {"text": "<钩子台词>", "start": 0.7,  "end": 4.6},
    {"text": "<正片卖点台词>", "start": 6.2,  "end": 10.2},
    {"text": "<CTA>", "start": 11.0, "end": 14.5}
  ],
  "chips": [{"text": "70mm迷你机身 · 轻巧便携", "start": 6.0, "end": 10.5}],
  "spec": {"items": ["74×39mm", "70g", "Type-C"], "start": 11.5, "end": 15.0},
  "compliance": "AI 生成内容 · 广告"
}
```
- `{"file": ...}` = **直接复用已有片段**，不必按 `<runid>_<seg>.mp4` 命名 → 新钩子配老正片就靠它。
- 每条变体跑一次 `make_ad.py <变体.json> --steps assemble,deliver`；`deliver.name_main` 写成人能看懂的名字（如 `01_冲突_车内_15s.mp4`）。
- ⚠️ **6 条必须串行跑**（共用 workdir，`overlay_cfg.json` 与 `ov_*.png` 会被互相覆盖）。
- ⚠️ 装配器读 `<workdir>/overlay_cfg.json` 取字幕 → make_ad 已把 `AD_TMP` 指到 workdir，换工程目录时别忘（否则 overlay PNG 落到 /tmp/r2v 互相踩）。

### 3. 产品锁缺口：机头会被画成「比机身宽的大圆盘」（本轮 3/3 全中）
只要分镜里出现「**机头正对镜头 / 侧过机头端详刀网**」，三段**全部**把机头画成宽于机身的大圆盘/蘑菇头（真机是等径直筒）。修法已写进共用模板 `templates/product_lock_head.txt`（所有产品继承）：
【机头与机身·最高优先级】机头直径**与机身直径相同**（相等或略小）…**绝不是比机身更宽的大圆盘、蘑菇头、飞碟形、喇叭形**；**不要拍"机头正对镜头"的特写**，最多**侧前方 3/4 视角**（同时看得见机身侧面与刀网边缘）。

同批另两条（也已进模板）：
- **别让机器凑近镜头**：钩子镜要写「**拿在胸前、不要高举也不要凑近镜头**」＋「长度不超过画面高六分之一」；不写会怼成近景（实测产品占画面高 1/3 ✗）。
- **镜子前的镜头容易正脸朝镜头**（像摆拍）→ 补「侧一点脸、看镜中的自己，不要正脸朝着镜头方向」。

**验收纪律**：改了锁也要**每轮重新放大核**。本轮 h1/h2 一次过，h3 因「凑近镜头＋正脸」再修一轮（只重跑 h3 单段 = 3 元，然后把 v5/v6 配置里的钩子来源指向新段即可）。

### 4. 成片核验两件工具
- **钩子归属核对**（防拼错段）：抽 2.0s 帧 → `scale=64:114,format=gray` 灰度 → 与各钩子段同秒帧算平均绝对差；最近者必须是期望的那个钩子。实测 **2.1~3.5（正确）vs 60~78（其他）**，区分度极大。⚠️ ffmpeg 输出裸像素**必须加 `-f rawvideo`**（`.raw` 后缀它认不出，报 muxer 错误）。
- **6 格总览图**：每条抽 1s/6s/12s 三帧拼网格 → 一眼看「CTA 字幕 + 参数条 + 合规标在不在、有没有价格、产品有没有变形」。
- ⚠️ `xstack` 布局要对**条目列表**截取 n 项，**绝不能对 join 后的字符串做 `[:n]`**（n=3 时会截成 `"0_0"` → ffmpeg `Invalid argument` / 写不出文件）。

### 5. 交付与投放建议
- 桌面目录用子文件夹（如 `~/Desktop/电商素材/<产品>/视频/15s钩子变体/`），文件名带钩子类型与场景（`01_冲突_车内_15s.mp4`）；发飞书时逐个 `feishu_send_media.py`（回显 `视频: 0 success` = 成功）。
- 报告口径：结论先行 + 6 条表格（钩子/场景/大小）+「同场景差异只在开头 5 秒」的说明 + 投放建议（**看 3 秒完播率**判断钩子强弱，砍弱留强，再对留下那条出 5-10 个变体）。

### 6. 改流水线后的自证（别只靠嘴说"没改坏"）
1. **复刻**：把上一版交付件的分段当输入 → `make_ad.py <项目.json> --steps assemble,deliver`
2. **比对**：`md5(新成片) == md5(已交付成片)`，**30s / 15s 双双一致**才算没改坏（2026-09-18 实测一致：30s `86f3da96…`、15s `0b67686b…`；不一致就说明动了不该动的层）
3. **冒烟**：生成链路（submit→fetch→verify）用**单段**真跑一次（10 秒 ≈ 6 元）即可确认，别整片跑通才验
4. **老路径回归**：跑一次"没人走的分支"（例：不带旁白的装配、带 trim 与不带 trim 各一次）—— 老 bug 常藏在这些分支里（2026-09-18 就是靠回归发现装配器音频链把 `asetpts` 写成 `setpts`，那条路从上线起就是坏的，因为所有成片都走旁白）。
