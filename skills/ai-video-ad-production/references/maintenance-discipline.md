## 2. 文档纪律（写之前必须看）

1. **新结论优先改既有文档**，禁止"每轮新建一篇 reference"。`references/` 只保留**主题总纲**（目标 ≤10 篇）：
   产品保真 / 引擎与模型 / 分辨率与成本欠费 / 流水线与核验 / 钩子与投放 / 配音与字幕 / 合规与参考图 / 场景剧情片。
2. 旧结论被推翻时，在被覆盖的位置写一行 `❌ 已作废（日期）：旧 → 现：新`，**不要另起一篇"更正文档"**
   （历史上正是这么涨到 53 篇的）。
3. SKILL.md 与本文件冲突时：**本文件（最新日期）优先**，并顺手把 SKILL.md 那处改掉。

## 3. 往 GitHub 同步（hermes-skills 仓库）铁律

- 🚨 **关于远端仓库的任何说法，必须现场调 API 核实**；本地工作树里有 ≠ 远端有。
  实例（2026-09-19 踩过）：曾断言"个人收款码已经在公开仓库里" → 实际 **2026-08-21 的 commit `1b7da405` 早已删除**，
  远端 `assets/` 整个目录 404。凭印象下结论 = 输出假信息。
- 工具链：
  - `~/.hermes/scripts/sync_skills_prep.py` —— 先做 **hash 差异分析**（新增 / 改动 / 一致三类 + 排除清单，
    例如个人收款码、手机号等不该公开的文件）。
  - `~/.hermes/scripts/sync_skills_repo.py` —— 走 contents API 推送 + **回读验证**（远端文件树 + 抽样 hash）。
  - 远端**删除**文件：contents API `GET` 拿完整 `sha` → `DELETE` + `{"sha":..., "branch":...}`。
- 公开仓库发布前必须：①凭据/手机号扫描并脱敏 ②排除个人收款码等私密素材 ③排除品牌产品图（侵权）。
- 元数据文件（README / `.claude-plugin/*.json`）改写要**可重复执行**：找不到 `old` 时先看 `new` 是否已在文本里，
  在就跳过，别硬失败（首次跑失败过一次，锚点写成了带粗体的形式，实际文件里没有粗体）。
- 大批量整理时：**先备份**（`tar -czf ~/.hermes/backups/skill-refs-<日期>.tar.gz ...`），
  并给"删旧文档"加**安全闸** —— 新文档缺一篇或任一 <800 字符就中止，不动旧文件。
