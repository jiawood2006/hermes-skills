**这篇管什么**：从「一条命令出片」到「交付到飞书」这条链上的一切 —— 整机六步流程、项目 JSON 字段、
装配与覆盖层、交付前核验清单、以及反复栽跟头的工具坑。产品保真的锁措辞、参考图选择、引擎横评、
投放指标各自另有专文，本文不重复。

**什么时候读**：接「做片 / 出片 / 交付 / 核验」需求时，动手前后各读一遍；改流水线、换引擎、
批量出变体、用户说「你先检查一下」时必读。

**配套**：用法与路径判断见 `SKILL.md`；产品锁模板 `templates/product_lock_head.txt`；
可跑样例 `templates/ad_project.hsq1.json`。ffmpeg/ffprobe 在 `~/video-tools/bin/`。

## 一、整机流程（`scripts/make_ad.py`）

### 1. 一条命令、六步、每步可单跑

```bash
S=~/.hermes/skills/ecommerce/ai-video-ad-production
python3 $S/scripts/make_ad.py $S/templates/ad_project.hsq1.json --steps plan
python3 $S/scripts/make_ad.py $S/templates/ad_project.hsq1.json --steps all
python3 $S/scripts/make_ad.py <项目.json> --steps assemble,deliver
python3 $S/scripts/make_ad.py <项目.json> --steps fetch,verify --seg 3 --runid v24 --res 720P
```

| 步 | 做什么 |
|---|---|
| `plan` | 由产品档案 + 分镜脚本生成每段完整 prompt（**免费，先看先审**）；`plan` 永远先跑，plan 失败则不提交任何任务（没花钱） |
| `submit` | 提交百炼，落 tasks json |
| `fetch` | 轮询 + 下载分段 mp4（存在性/大小校验） |
| `verify` | ffprobe + 抽帧核验图（9 格全景 + 产品 2 倍特写） |
| `assemble` | 旁白（edge-tts）+ 字幕/花字/参数条/合规 → 30s 成片 → 再切 15s 版 |
| `deliver` | 按配置拷到 `~/Desktop/电商素材/<产品>/视频/` |

可选参数：`--steps` / `--seg` / `--runid` / `--res`（也支持 `--steps=` 等号形式）。
每步都查退出码 + 产物存在/大小，不达标直接报 FAIL 原文并逐条列出，**不静默继续**；
结尾给一行结论（`✅ 全部步骤通过` / `❌ 有失败项，逐条如下`）。

### 2. 部件已打通（勿再按「待补」理解）

- **产品档案**：`ecommerce-material-studio/references/product_profiles.json`（本项目键 `haier_hsq1_shaver`，
  含 `physical / key_selling_points / assets / video_lock / video / image` 段）。
  生图读 `image`，视频读 `video` + `video_lock` → **改档案一处，图/视频同时生效**。
- **产品锁**：所有产品共用 `templates/product_lock_head.txt`（`{{字段}}` 由档案 `video_lock` 填）。
  锁里的话是调过很多轮的措辞 —— **分镜里不要重复写，也不要手写新模板**。
- `ecommerce-material-studio`（素材工厂）= **仍只做图**；`video-composer-v4` 仍是旧路线
  （示例脚本是空壳），**别用它做 R2V 出片**。

### 3. 改流水线 / 加功能后必须自证（不许只说「没改坏」）

1. **复刻**：拿上一版交付件当输入 → `make_ad.py <项目.json> --steps assemble,deliver`
2. **比对 md5**：`md5(新) == md5(已交付)`，**30s / 15s 双双一致**才算没改坏
   （2026-09-18 实测一致：30s `86f3da96…`、15s `0b67686b…`；不一致 = 动了不该动的层）
3. **单段冒烟**：生成链路（submit→fetch→verify）用**一段**真跑即可（10 秒 ≈ 6 元），
   别等整片跑通才验，也别为了「完整」整片重跑烧钱
4. **老路径回归**：跑一次「没人走的分支」——**老 bug 就藏在那里**。
   2026-09-18 抓到两处：装配器音频链把 `asetpts` 写成 `setpts`（`setpts` 是**视频**滤镜）→
   ffmpeg 报 `Media type mismatch ... atrim(audio) 与 setpts(video)`，**该路径从上线起就是坏的**；
   `xstack` 布局被**按字符**截断（`"...".join(items)[:n]` 应写成 `"|".join(items[:n])`）→
   段数少时 9 格拼图直接写不出文件（`Nothing was written into output file`）。
   → 回归用例：**不带旁白的装配 + 带 trim + 不带 trim**，各跑一次。

### 4. 引擎选择（项目 JSON 加一行 `model`）

```json
{ "runid": "wh", "model": "wan3.0-video", "resolution": "720P", "duration": 5, "ratio": "9:16" }
```

`step_submit` 按模型自动切换 input 形态（2026-09-18 补丁：先 `model = proj.get("model", "wan2.7-r2v")`，
再 `if "3.0" in model:` 分支）：

| 引擎 | 参考图字段 | 备注 |
|---|---|---|
| `wan3.0-video`（产品镜主力） | `input.images = [url, ...]` | 自动带 `parameters.watermark = false`（默认可能烧水印） |
| `wan2.7-r2v`（纯人物戏） | `input.media = [{"type":"reference_image","url":...}]` | **不写 `model` 时的默认值** |

| 用途 | 引擎 | 关键限制 |
|---|---|---|
| **产品镜**（画面里有产品） | **`wan3.0-video`** ✅ 主力 | 0.6 元/秒；免开通；支持 30s；产品一次就对、整段不掉金 |
| **纯人物戏**（不出产品） | `kling-v3-omni` ✅ 真人质感最好 | **prompt 硬上限 2500 字符**（产品锁 2600 字会报 `size must be between 0 and 2500`，失败不计费）；产品整段会崩 |
| 最便宜档（非产品镜） | `pixverse-v6-r2v-omni` | 0.27 元/秒；但把产品画成超大罐子 |
| ✗ | `vidu-q3-ad` | 720P 下吐横屏（字段不吃 9:16） |
| ✗ 服务端不可用 | `wan2.1-vace-plus` | `Failed to invoke scheduler`（换真机路线暂不可用） |

> ❌ 已作废（2026-09-18）：路径①「`wan2.7-r2v` 是当前主线」→ 现：**产品镜 = `wan3.0-video`**，
> `wan2.7-r2v` 产品镜退役（产品小／看不清／洗成银白＝反复返工根因），只留不挑产品的镜头。

**`duration` 是项目级字段** → 5s 段和 10s 段不能放同一个项目，按段时长拆成多个 JSON 顺序跑
（本轮：`project_w30_hooks.json` = 3×5s，`project_w30_body.json` = 2×10s），还能分别核验、失败只重跑一半。

### 5. 分段重做（只重跑有问题的段）

核验后**逐段给放行/重做结论**，然后：

1. 新起 runid（如 `w2h` / `w2b`），只放要重做的段 → `plan,submit,fetch`（只花这几段的钱）
2. 旧成片先**归档**再覆盖：`_停用_<原因>版/`（如 `_停用_R2V产品镜版/`）—— **别让用户分不清哪版是新的**
3. 改 `variants/*.json` 与主片 json 的 **`assembly.order[].file` 引用**指向新段（纯本地，0 元）
4. 跑 `--steps assemble,deliver` 重建；交付文件名**带引擎/版本标识**（如 `hsq1_wan30版_30s.mp4`），
   不要沿用会误导的旧名（旧名写着 `R2V版` 却塞 wan3.0 的片）

换引擎**不必整片重来**：只重生成「画面里有产品」的段，其余段沿用旧产物，`--steps assemble,deliver`（**0 元**）重建全部成片。

### 6. 批量 15s 钩子变体（用户说「跑 6 条看看」）

3 种钩子 × 2 个场景 = 6 条 15s，目标是**一次拿到 6 个可投放素材，用真实数据淘汰**。

| 部分 | 做法 | 成本 |
|---|---|---|
| 钩子段 | 3 段**新生成**（各 5s） | 5s×0.6 元 = **3 元/段**，共 9 元 |
| 正片段 | **复用已通过核验的老素材**（各 10s） | **0 元** |
| 装配/切条/交付 | `assemble,deliver` | **0 元** |

`assembly.order` 支持 `{"file": "/tmp/r2v/xxx.mp4", "trim": 10}` **直接引用已有片段**，
不必按 `<runid>_<seg>.mp4` 命名 → 新钩子配老正片就靠它。
同场景的两条差异只在开头 5 秒 = 变量唯一，交付时要主动向用户说明。
⚠️ **6 条必须串行跑**（共用 workdir，`overlay_cfg.json` 与 `ov_*.png` 会互相覆盖）；
装配器读 `<workdir>/overlay_cfg.json` 取字幕 → make_ad 已把 `AD_TMP` 指到 workdir。

15s 转化版结构：0–5s 钩子 → 5–15s 正片 → 结尾 **CTA「点下方小黄车」** + 顶部花字 + 参数条 +
右下「AI生成内容 · 广告」。价格按用户铁律**不入画面**（价格常变）；但**动作引导必须有**。

### 7. 成本与协作口径

- r2v：一段 = 10 秒 = 3 个镜头 = **6 元/段 + 约 15 分钟；没有「只重跑某一个镜头」的选项**。
- 实测一轮：第一轮 21 元（3 钩子 9 + 正片/车内 12）→ 核验后定点重做 4 段 18 元，**累计 39 元**；
  装配/重建/交付全 0 元。用户接受「先花小钱验证、再定点重做」，不接受「闷头重抽整片」。
- 报账要按「本轮花了多少 + 累计」报，并说清**失败/重跑部分是否计费**。
- 用户说「我不专业，还是按照你的建议来做」时：❌ 不要再抛选项让他挑；✅ 直接执行自己推荐的那一档，
  执行前一句话说清「做什么 / 花多少钱 / 多久」，开跑与核验后各报一次进度，收尾把账目报清。

## 二、项目 JSON 字段

| 字段 | 说明 |
|---|---|
| `runid` | 段文件名前缀 / 版本号 |
| `product` | 指向产品档案 `product_profiles.json` 的键 —— **生图/视频共用同一份档案** |
| `workdir` | 工程目录（默认 `/tmp/r2v`）；`AD_TMP` / `VO_WORKDIR` 跟随它 |
| `model` | 引擎（见 §一.4）；不写 = `wan2.7-r2v` |
| `resolution` / `duration` / `ratio` / `prompt_extend` | 如 `720P` / `10` / `9:16` / `false` |
| `refs` | 参考图顺序 = 图1..图N，**必须与产品锁模板里的图号描述一一对应**；本地图自动 scp 到公网 |
| `segments` | `seg1/seg2/...` 每段分镜正文（**只写「拍什么」**；产品锁由 make_ad 自动拼在前面） |
| `verify.zoom` | 抽帧放大核验点：`[["seg2",5.0],["seg3",1.5],["seg3",6.0]]` |
| `assembly` | 见下 |
| `deliver` | 交付目录 + 文件名（默认 `~/Desktop/电商素材/<产品>/视频/`；`deliver.name_main` 写成人看得懂的名字，如 `01_冲突_车内_15s.mp4`） |

**`refs` 实际样例**（`ad_project.hsq1.json`，顺序不可换）：

| 图 | key | 内容 |
|---|---|---|
| 图1 | `mesh_gold` | 刀网微距（金色校准） |
| 图2 | `front` | 正面全身（形态/长径比） |
| 图3 | `hand` | 真手比例 |
| 图4 | `base` | 底部端面（充电口） |
| 图5 | `char_man_v15` | 男主（本地图，自动 scp） |

**`assembly` 结构**：

| 键 | 内容 |
|---|---|
| `order` | 段序列：`{"seg":"seg1"}` 或 `{"file":"...mp4","trim":10,"label":"车内"}` |
| `total` | 成片总长（30.0 / 15.0） |
| `vo` | `{"file":"vo30_yunxi.mp3","voice":"zh-CN-YunxiNeural","rate":"+5%","build":true}` |
| `subs` | `[{"text":"...","start":1.3,"end":3.95}, ...]` |

| `cut15` | 15s 版：`total` / `order`（可 `trim`）/ `vo_ranges`（旁白切哪几刀）/ `overlays`（每个 overlay 在 15s 轴上的新时间窗） |

## 三、装配与覆盖层

### 1. 旁白：落点 = 字幕 `start`（天生对齐）

`scripts/build_vo30.py` 读 `<workdir>/overlay_cfg.json`，**按每条字幕的 `start` 逐句排 TTS** →
**改字幕时间 = 旁白自动重排对齐** ✓，不要凭猜改时间轴。
环境变量：`VO_WORKDIR`（工程目录）、`VO_DURATION`（**必须等于成片总长**，make_ad 取 `assembly.total`）、
`FFMPEG`、`EDGE_TTS`。
配音：edge-tts `zh-CN-YunxiNeural`（本项目 `--rate=+5%`，早期配方用 `+18%`）。

### 2. 覆盖层（字幕 / 花字 / 参数条 / 合规标）

PIL 画 1080×1920 **透明 PNG** → `overlay=0:0:enable='between(t,a,b)'` 定时显示，比 `drawtext` 稳
（中文字体、多行、圆角底都好控）。**PNG 命名要统一**（曾因 `ov_sub1.png` vs `ov_sub_1.png` 不一致空跑一次）。

### 3. 装配的工程约束（写新功能时别踩）

- **多产品并行必须各用各的 `workdir`**：`AD_TMP` / `VO_WORKDIR` 要跟随 workdir，
  否则 overlay PNG 落到同一个 `/tmp/r2v` 互相覆盖，15s 版会复用错图。
- **VO 输入必须追加在 overlay 输入之后**：overlay 的输入序号靠 `len(inputs)//2` 定位，
  中间插一个音频会让后面所有 overlay 索引错位。
- **用 VO 时不要生成段内音频链**：未消费的 filter 输出会被 ffmpeg 判为未连接而报错。
- **生成一律 720P**：同 prompt 跑 1080P 会把产品画坏（长径比 1.25 矮胖罐 + 金网消失）。

### 4. 一步出片（配音装配，秒级 · 避免挂死）

```bash
ffmpeg -loglevel error -y -i 静音视频串.mp4 -i s1.mp3 -i s2.mp3 ... \
  -filter_complex "[1]adelay=150|150[a0];[2]adelay=2620|2620[a1];...;\
[a0][a1]...amix=inputs=N:normalize=0,afade=t=out:st=<总长-0.7>:d=0.7,apad=pad_dur=0.4[a]" \
  -map 0:v -map "[a]" -t <总长> -shortest -c:v copy -c:a aac -b:a 160k -movflags +faststart OUT.mp4
```

- ⚠️ **裸 `apad` = 无限静音流**：`-t`/`-shortest` 在 filtergraph 出口不必然终止 → 编码器空转 6 分钟、
  写出 16MB、`moov atom not found`、单进程 110% CPU。**必须 `apad=pad_dur=0.4`。**
- **别先导 m4a 再 mux**（多一步 = 多一个挂死点）；音频序号从 `[1]` 起（0 是视频串）。
- 台词时长按 mp3 实测，**末句结束时间必须 ≤ 视频长度**，否则尾字被切（如末句 1.66s 就要放在 ≤13.34s）。
- 多段拼接：每段先 `scale=1080:1920,setsar=1` 再 `concat`；裁短版（15s）用
  `trim=0:<秒>,setpts=PTS-STARTPTS`（视频）与 `atrim=0:<秒>,asetpts=PTS-STARTPTS`（音频）**配对**，否则音画错位。
- 30s 拼装要把 15s 的末尾 CTA 镜算进前半段（漏算 → 只出 28.08s / 28s）。

### 5. 官方真像素插入镜（产品镜的终极解）

**触发条件**（满足任一即换路线，不要再改 prompt）：中景手持镜的产品形态**反复修不好**；
用户说「认不出是什么 / 不像真机 / 产品太小 / 刀网不对」且已按锁改过 2 轮；投放素材要求「产品必须真实」。
**铁律依据**：用户定的「**同缺陷改 prompt 修 2 次不根治 → 停手换路线/换引擎**」。
AI 生成的产品只适合「生活情景里的道具」，**产品必须被认出来的镜头交给真像素**。

**片内结构（15s 变体）**：

```
[钩子 5s（AI，人物/情绪）] + [官方真机产品镜 3s（真像素，零 API 成本）] + [正片 7s（AI，截短）] = 15s
```

- 正片从 10s **截到 7s**：给官方镜腾时长，并顺手避开原正片尾部的瑕疵镜（场景漂移、镜面花屏）。
- 官方镜放在 **5~8s**（钩子看完、正片开始，观众需要看清产品是什么的时候）；
  **不要**放片尾（会和 CTA/参数条抢注意力）。

**脚本**：`scripts/build_official_product_insert.py`（原 `/tmp/build_official2.py` 入库版）。
内容 = 三个真像素特写各 1s，缓慢推近（`zoompan z='min(zoom+0.0006,1.06)'`），之间 0.15s 交叉溶解：

| 镜 | 素材 | 处理 |
|---|---|---|
| 1 | `拉页图/拉页图-7.jpg` | **裁掉左侧中文文案与底部标注**（本项目 `crop(118,480,556,1105)`）；只留金网+深灰底 |
| 2 | `产品图/正面图_cropped.png` | **白底必须抠成透明**（否则贴上深灰底露出白色矩形 ✗）；合成到深灰径向渐变底，产品占宽 ~0.62 |
| 3 | `产品图/3.png` | 先自动求**非白内容包围盒**定位端面，再按 9:16 裁 + 抠白底；展示电源键＋Type-C |

背景统一用**深灰径向渐变**（与拉页图-7 的深色背景一致），三帧色调才连贯。

**三个必踩的坑**：
1. **白底不抠 → 露出矩形**：官方产品图多是白底不透明 PNG，直接 paste 会在深色底上留下白色方块。
   做法：像素级把接近纯白的区域置透明、边缘按阈值羽化。
2. **官方图带中文文案/标注**：拉页图左侧有卖点文案、底部有参数标注 → 裁图必须避开。
3. **插入段必须带一条静音音轨**：装配器按段取音频流，**没有音轨的段会直接报错**。
   做法：`ffmpeg -i official.mp4 -f lavfi -i anullsrc=channel_layout=stereo:sample_rate=44100 -shortest -c:v copy -c:a aac`。

**接进变体时间轴**：插入 3s 后**所有 overlay 时间整体 +3s**（否则字幕/花字/参数条与画面错位）——
`start ≥ 5.0s` 的字幕/花字 → `start = min(start+3, 13.0)`、`end = min(end+3, 14.9)`；
参数条锚到 `12.6~14.9`；CTA 落在末尾 1.5~2s 内即可。
**旁白不用手工重做**（按字幕 `start` 自动重排，见 §三.1）。
官方段配一句**官方原文**旁白（本项目「全新镀钛刀网，持久耐用更锋利。」），否则 5~8s 会出现 1s+ 无语音空白。

**成本**：官方插入镜 **0 元**（纯 ffmpeg + PIL，无 API）；重装配 6 条变体 **0 元** →
「AI 画不像」时换真像素路线的**边际成本是 0**，没有理由继续重 roll 抽卡。

### 6. 产品保真两条硬事实（2026-09-19 定论，覆盖旧写法）

- **手持比例 = 0.7~0.8 倍手掌长**。真机 HSQ1 = 74mm 长，成人掌长约 100mm →
  机身总长 ≈ 手掌长的 0.7~0.8 倍（比手掌略短，约一根食指长）。
  现行锁措辞：「不少于画面高度的八分之一」+「手持时机身总长 ≈ 手掌长 **0.7~0.8 倍**」+
  「**绝不许比他的手掌还长**（画长了就变成保温杯／水杯）」。
  > ❌ 已作废（2026-09-19）：机身 ≈ 手掌长 **1.1~1.3 倍** → 现：**0.7~0.8 倍**（1.1~1.3 会让 AI 把机器画得比手掌还长，侧视 = 保温杯）。

> ❌ 已作废（2026-09-16）：产品特写作「官方真机图 Ken Burns / 整屏贴图 + 大字」→ 现：**官方真像素插入镜（3s 段）**；

> ❌ 已作废（2026-09-16）：合成卡 / 产品卡贴片 / 抠图叠背景当交付路线 → 现：AI 场景镜（`wan3.0-video`）+ 官方真像素插入镜（保细节但不保真实感，用户一律否决）。

## 四、交付前核验清单（逐项必过，缺一项不算交付）

**核验方式**：抽帧拼图 + vision 放大核产品（形态 / 刀网饱和金 / logo / 尺寸 / 镜子）。
**「看起来没问题」不算过检**，必须放大到产品区 2~3 倍逐项核（用户一句「好了吗，你先检查一下」曾查出 3 处真实缺陷）。

### 1. 规格与运动

- **规格**：`ffprobe` → 30s 版 = `30.000000`、15s 版 = `15.000000`、**1080×1920**、25fps、h264 + aac 齐。
- **真运动**：`freezedetect=n=-60dB:d=0.8` 数 `freeze_start`，**必须 0**。
  ⚠️ 它**测不出「静图 + zoompan」** → 是否「贴图感」只能靠肉眼/视觉复核。
- **音轨**：`volumedetect` mean ≈ **-20~-26dB**、max **< -1dB**（不削波）；抽查各语音段约 -27dB 表示有声。

### 2. 语音落点与字幕

- `silencedetect=n=-38dB:d=0.15` 读 silence_start/end **成对** → 每句台词落在**对应镜头内**。
  ⚠️ 别把「句中停顿」误读成「句首静音」：edge-tts 句首静音只有 ~0.18s，正常（曾据此误判「配音晚 1.3 秒」）。
- **字幕时间轴只用精确抽帧，不要用抽样拼图**：
  `fps=1/3.75,tile=4x2` 抽样帧的时间标签与实际时间并不对应，据此改时间轴 = 白改 ✗。
  正解：`-ss` 必须放在 `-i` **前面**逐帧抽，再拼图逐格核对：
  ```bash
  for t in 2.0 5.5 15.0 18.0 22.0 25.0; do
    ffmpeg -loglevel error -y -ss $t -i out.mp4 -frames:v 1 -vf scale=360:-1 f_$t.jpg
  done
  ```
  现成实现：`scripts/assemble_r2v_overlays.py --sync out.mp4 2.0,5.5,15.0,18.0,22.0,25.0`
  （6 个时间点核验 6/6 对齐 ✓ 而抽样拼图给出的结论是错的）。
- **字幕落点的时间轴从哪来**：`vad_filter=True`（默认）会把相邻两句并成一个 span，拿不到断句位置 ✗ →
  正解 `vad_filter=False, word_timestamps=True` 读**词级**时间，取该句首词的 start 作字幕起点。
  现成实现：`scripts/stt_dialogue_check.py --words seg2.mp4`。
- **台词反查：判据是语义，不是字面**。r2v 自带人声会**读错**（本项目 seg3 前 5 秒转写成乱码 → **该段重跑**）；
  但**同音字属正常**（刮→挂、八千五百→8500、几下就要干净→几下就干净），**只有整句语义乱掉才算失败**，
  别为同音字反复重跑烧钱。

### 3. 跨镜头一致性（段落各自合格 ≠ 连起来合格）

| 类型 | 读数方法 | 通过线 | 本项目翻车记录 |
|---|---|---|---|
| **产品尺寸（跨镜头）** | `scripts/scale_panel_check.py out.jpg --panel "official:<官方真人实拍帧>" --panel "shave:<成片>@8.5" --panel "wash:<成片>@21.5"` → 数每格产品/手/头占几格，比「产品÷手(或头)」 | 各镜头比值彼此接近，且与官方帧一致 | 水洗镜头放大约 **2.5~3 倍**；剃须镜头偏小约 **35%**（用户两次同样指出） |
| **音色（多段拼接）** | `scripts/voice_consistency_check.py`（基频中位差）+ **同内容**谱相似度 | 基频段间差 **≤15%**；同内容相似度 **≥0.99** | 三段 125/168/154 Hz（差 23~35%）=「像换了三个人」 |
| **接口/按键位置** | 抽帧放大与官方图并排（官方 `产品图/3.png` = 底部端面） | 位置、朝向一致 | AI 把 Type-C 线插到**机身侧面**（真机在底部端面） |
| **字幕时间轴** | `-ss <精确秒>` 单帧核对每个句子中点 | 全部落在对应语音窗口内 | 用 `fps=1/N` 抽样会读出假的提前/延后 |

**两条已验证的修法（都跑通过，别再自创）**：

1. **尺寸不一致 → 相对人体比例锚点 + 特写单独成段**：
   有效锚点（模型能听懂）=「产品总长 ≈ 男主头高（发际线→下巴）的 1/3」
   ＋「握着时手掌能整个包住机身、五指合拢绕过机身背面」（「手能不能握住」比数值敏感得多）。
   **不要写厘米**（「7cm」模型不认）。同一段 prompt 里同时有远景和特写 → 特写仍被放大，**特写镜头单独出一段**。
   实测：加锚点后剃须镜头产品从 1.3 格 → 1.9 格（+46%）；水洗从 7 格 → 1 格（中景化后回归正常）。
2. **音色不一致 → 定稿要「全片我方 TTS + videoretalk」**：`reference_voice`（≤10s）**只把基频拉近**，
   音色仍各段不同（实测各段与参考音同内容相似度仅 0.84~0.89，而「不同人」基准就在这个区间）。
   定稿流水线：三段全部换我方 TTS 配音 → 有正脸说话镜头的段走 `videoretalk` 重对口型 →
   **实测 videoretalk 原样保留我方音频**（同内容相似度 **1.000**、F0 与配音一致）；无正脸段（手部/产品特写）
   直接 `scripts/replace_segment_audio.py` 换音轨。模型会「自己多说」乱码句（prompt 写「台词只说一遍」也拦不住）
   → 判据 = **逐段 STT 反查出现没写过的句子**，该段音频必须换掉。

**两个方法论坑**：①**比音色必须「同内容」比**——跨段不同台词做谱相似度无效，差异由台词内容主导（曾据此误判
「videoretalk 改变了音色」）；②**别用抽样帧判断时间轴**。

### 4. 成片级最后一道（逐段通过 ≠ 成片通过）

抽帧 9~10 格（覆盖每句字幕、每个花字的起点）一次核完：

- [ ] 每句**字幕**文字正确、无遮挡、无错位；无乱码文字、无水印、无多余接口
- [ ] 花字/参数条文字正确；**画面里没有任何价格**（用户硬要求「价格经常变化」：参数条只留尺寸/重量/接口）
- [ ] 右下角「**AI生成内容·广告**」合规标注在位
- [ ] **产品细节**：对**交付文件**（不是中间素材）裁产品区放大 2~3 倍 → 金网有编织网孔（不是色块/粗环）、
      Haier 字母正确、机身渐变锐利
- [ ] **贴片遮挡**：胶囊/贴纸**不得盖住 Haier 或刀网**；**文字不压产品**（¥169 与角标至少留 70px）
- [ ] **特效边界**：PIL 画的「水流 / 光扫」必须 `GaussianBlur` 软化
- [ ] `ffprobe`：30s = `30.000000`、15s = `15.000000`、`1080×1920`
- [ ] 交付 = 覆盖桌面既有交付名（`hsq1_R2V版_30s/15s.mp4`），**旧版先改名归档**（`…_v15_30s.mp4`）再覆盖

### 5. 官方插入镜版专项核验（不许跳过）

1. **抽帧必须含官方段**：`2s`（钩子）/ `6.5s`（官方产品镜）/ `13s`（CTA＋参数条）三点各一帧拼图肉眼核。

3. 音频：`volumedetect` 抽查各语音段 `mean_volume`（约 -27dB 表示有声）、

## 五、工具坑（都栽过，按此避开）

### 1. 脚本与命令

- **写脚本一律 `write_file` 直接落盘**，**不要用 shell heredoc（`python3 - <<'EOF'`）拼**：
  heredoc 里的 `\n` 转义会被毁，产出语法错误的脚本（曾两次 `SyntaxError: EOL while scanning string literal`，
  另一次 `re.sub(BODY…)` 把字典截断只写了 4739 字节）。改脚本优先 `patch`（改一处）或 `write_file`（整份重写），
  **改完先 `python3 -c "import ast;ast.parse(open('x.py').read())"` 验语法再提交**。
- `terminal` 报 `cd: <某个不存在路径>: No such file or directory`（会话 cwd 失效、后续命令全部 exit 126）→
  **显式传 `workdir`** 即可恢复，不必重建会话。
- 含中文/空格的目录做 `ls`/`cp`/glob 时容易失配 → 改用 Python（`shutil.copy2` / `os.listdir`）。
- 后台长任务：一次提交多段后，用 `background=true` + `notify_on_complete=true` 跑 fetch 轮询脚本，
  不要在 foreground 里 sleep 等待。

### 2. ffmpeg / ffprobe

- **裸 `apad` = 无限静音流**（见 §三.4）。
- `xstack` 布局要对**条目列表**截取 n 项，**绝不能对 join 后的字符串做 `[:n]`**（n=3 时截成 `"0_0"` →
  `Invalid argument` / `Nothing was written into output file`）。
- 装配器音频链曾把 `asetpts` 写成 `setpts` → `Media type mismatch`（该分支从上线起就是坏的，回归用例必跑）。
- 输出裸像素**必须 `-f rawvideo`**。
- `-ss` 放 `-i` **前**才是精确定位；抽样/概率抽帧不能用于判断时间轴。

### 3. 其它反复出现的问题

- **任务跟踪 JSON 要合并不要覆盖**：`json.dump({tag: tid})` 覆盖写会丢掉上一个任务 id；提交脚本一律 `d.update(ids)`。
- 用户会**逐镜挑问题**且眼光很准（「产品高度有点高了」→实测 2.56 vs 真机 1.93）→ 他指出的每一处
  **先用像素/标尺确认数量级**再改，别凭感觉改措辞；修完**顺手把同类镜一起过一遍**。
- 反馈措辞往往很短（「尺寸不对 太长了」「又是侧面充电」）→ 自己判定是「比例问题」还是「画面占比问题」，
  必要时两者一起改。
- 「为什么别人能做的很好，要找思路找技能找方案」→ 遇到「别人做得好／我做不出来」，
  **先 `skill_view` 本技能的 references/**，再决定做什么；不要在已作废路线上自摸重推。
- 交付话术：**先给结论 + 一张读数表**，再给文件路径与大小；过程细节留在文档里，不要写成流水账。
