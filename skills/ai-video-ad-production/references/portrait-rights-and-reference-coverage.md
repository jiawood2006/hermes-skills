# 两条硬规则：肖像权 + 参考图覆盖（2026-09-17 用户明确要求）

> 这两条优先级高于其他一切制作技巧。做任何 AI 人物片之前先过一遍。
> ⚠️ 本文第 ② 条**修正** SKILL.md「用户偏好」段里那条旧结论，以本文为准。

## ① 肖像权：真人照片只取风格，不取脸

**用户原话**：「我发的人物照片不要完全按照照片来，那是真人的形象，容易造成肖像权问题，参考就行」

场景：用户发来一张真人照片或 AI 头像（例如水印为「豆包AI生成」的商务男士形象图），
接着说「像这种」/「参考就行」。**这时不要照着他的脸生成**。

正确做法：
1. **纯文字生成原创脸**（**不把那照片喂给模型**）—— 只保留他要的**风格元素**：
   眼镜 / 西装 / 领带 / 年龄段 / 气质 / 场景调性。
   生成 prompt 里可以直接写「黑色方框眼镜，深色西装＋白条纹衬衫＋蓝色条纹领带，27岁左右中国男性」这类风格描述。
2. 出 3~4 个候选 → 拼图发飞书让他挑（他回得很快）。**别自己拍板选脸** —— 换角是口味问题。
3. **核对新脸与照片不是同一个人**（脸型、五官结构要明显不同），并尽量选**中性、不像明星**的脸型
   （像明星的脸同样有肖像权风险）。
4. 已经**照脸生成过**的成片要**撤下、不投放**：本项目把这版移到 `视频/_停用_真人形象版/`，并在消息里明确告知用户。
5. 用户没说"用我"，就默认照片上的人**不是他本人** —— 不要把它当品牌代言人用在对外物料。

配套：换角后**所有含袖口/衣着的段落都要一起重出**（西装 ↔ 衬衫不能混），
水洗/充电这类"没有人脸但有手和袖子"的段落最容易漏。详见 `references/wan27-r2v-product-lock.md`。

## ② 参考图要"覆盖会被挑错的每个面"，不是"只留同一个视角"

**SKILL.md 里仍写着**："参考图两张必须同向同形态…**禁止**混入俯视/仰视/断面图当参考"。
**那条是错的，别照做** —— 写它时把一次失败归因错了。

2026-09-17 实测结论：**正面图 + 官方底部端面视图 + 真手握持局部，三张一起喂，产品反而最准**。
当初"变矮胖杯"的真因不是"多了一个视角"，而是**参考图没有覆盖到关键部位**。

| 症状 | 真因 | 修法 |
|---|---|---|
| **Type-C 口被画到机身正面** | 只喂了正面图，模型**没见过底部端面**，只能自己编 | 补官方底部视图（`3.png`：端面电源键同心环 + Type-C 插孔 + 指示灯）当第 3 张参考图 → 正面/侧面开孔归零 |
| **机身被画成矮胖杯**（长:径 1.3~1.5，真机 1.9） | 没有任何一张图能提供"粗细"参照 | 补官方**真手握持局部**（裁掉人脸、只留手＋机身、避开画面原有文字）当第 4 张参考图，prompt 写「图4 只用于参照粗细，不要抄它的色调/背景/服装/构图」 |

**通用规则：产品上任何用户会挑错的部位（接口 / 按键 / logo / 刀网纹理 / 粗细），
都必须有一张参考图能看见它。** 看不见的部位，写多少文字约束都挡不住模型自己编 ——
这个项目里"充电口画错"改 3 轮文案全无效，补一张参考图当场解决。

参考图做法：裁到主体或局部 → 转 JPG（去透明通道）→ `scp` 到 `/opt/yunvela-site/dh/` →
`curl -I` 必须 200 → prompt 里用「图1/图2/图3/图4」逐张说明每张的用途。
