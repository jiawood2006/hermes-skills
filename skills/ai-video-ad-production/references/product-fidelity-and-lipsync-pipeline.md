# 产品保真 + 人物真实感 流水线（2026-09-16 实测定型）

> ⭐ **首选解法已升级为「首帧法」**：直接用官方实拍照片做第一帧（`first_frame`），
> 产品就是官方真像素 → 尺寸/形态/logo 天然正确，且人物也是真人。
> 完整做法、字段、素材选取与 15s 成片模板见 **`product-scale-and-firstframe-method.md`**。
> 本文的「产品贴回」仍作**补救/精修**手段（例如已有成片里产品不对时）。
> 用户对尺寸的判定标准：**产品被放大 1.5~2 倍 = 严重失真**（真机鸡蛋大小 → 画面里像易拉罐）。

用户验收焦点：**产品不能失真、人物要有真实感**。这两件事**都不是靠"提示词写得更狠"解决的**，
而是靠素材纪律 + 工序分工。下面是踩了一整轮（十余条成片、约 85 元）换来的结论。

## 三段式分工（核心结论）

| 环节 | 谁来做 | 为什么 |
|---|---|---|
| 人物 + 场景 + 口型动作 | **AI 视频模型**（可灵 omni / 万相3.0 / PixVerse V6） | 模型的强项 |
| **产品外观** | **「产品贴回」`wan2.7-videoedit`**（把成片里的产品替换成官方真图） | 模型画不准精细产品：实测被画成大保温杯 / 蘑菇头金盘 / 放射网 / 帧间漂移 |
| 配音 + 口型 | **本地 edge-tts + `videoretalk`** | 文案音色可控，口型严丝合缝 |

**铁律：不要让同一个模型同时负责"画人"和"画产品"** —— 实测 100% 崩（产品尺寸/形态至少错一处）。
正确姿势是：生成镜头时**别给产品下过多细节约束**（越描述越容易被它放大/变形），
产品交给贴回工序，一步到位 100% 保真。

## 三个"看不见"的失真根因（按优先级排查）

1. **参考图没生效**（字段/模型写错 → 模型走训练先验）
   各家的正确写法见 `four-model-video-benchmark.md` 的「⭐ 参考图正确用法」表。
   典型症状：产品总是被画成"常见的同类产品形态"（迷你剃须刀 → 细长笔形），加多少负面词都没用。
2. **参考图被"污染"**（参考图里混进了形态错误的同一产品）
   实测：人物参考图 `hsq1_girl.jpg` 是一张 AI 图，她手里那把产品的形态是**错的**（齿状梳刀头+细长机身），
   结果模型在三张冲突参考里摇摆 → 中景帧变成"推子"、顶部变"蘑菇头"。
   **做法**：每张参考图入池前**逐张看图**，把与目标形态冲突的主体**裁掉**（本项目把她手里的产品裁干净，
   只留头肩 → 纯人物参考图），再上传公网。
3. **缺"尺寸锚点"**（模型把产品放大成杯子）
   只写"举到胸前展示"时，模型自动把产品放大到**比人躯干还大**（像保温杯）。
   提示词加客观尺度参照后立刻修正：
   > 这件产品非常小：长约 7 厘米、直径约 4 厘米，握在手心里只占手掌的三分之二宽，比他的拳头还小；
   > 严格按这个尺寸，不要把它放大成杯子、保温杯或罐子的尺寸。
   负面词同步加"产品被放大、杯子大小、保温杯、罐子、音箱"。

## 人物真实感 = 参考素材决定，不是提示词

- 喂 **AI 磨皮人物图** → 输出必然是 AI 脸（皮肤光滑无毛孔、牙齿假白、网红精修），
  提示词里写"真实肤质/不磨皮"+负面"塑料感、过度磨皮、网红脸"**压不住**。
- **素材来源优先级**：客户官方物料（拉页图/详情页/宣传片里的真人）> 真实拍摄照片 > AI 生成图。
  实测：换成官方拉页里的真人素材后，人物明显更真实（面颊结构、眉眼神态、胡茬细节都出来了）。
- 顺手一查：官方拉页里往往还有**真实使用场景照**（车载/办公/约会/出差）和**产品结构特写**，
  这些比我们自己造的素材强得多——**先翻客户物料，再考虑自己造图**。

## 产品贴回（wan2.7-videoedit）配方

```json
{"model":"wan2.7-videoedit",
 "input":{"prompt":"把视频中的<商品>替换成参考图1 里的<商品>：严格保持参考图1 的形状、比例、颜色、材质与 logo 一致，产品的位置、大小、朝向跟随原视频，不要改变产品的尺寸。画面其余内容（人物、动作、镜头运动、光线、背景）保持不变。",
          "media":[{"type":"video","url":"<待编辑视频公网URL>"},
                   {"type":"reference_image","url":"<官方产品图公网URL>"}]},
 "parameters":{"resolution":"720P","prompt_extend":false,"watermark":false}}
```
- 官方文档里这类"指令 + 参考图"的示例就是**局部替换**（原文示例：`将视频中女孩的衣服替换为图片中的衣服`）。
- 输入视频必须是**公网可访问 URL**（`reference_image` 才接受 base64）。
- 输出 **720P**（比源片低），需要 1080P 时最后再放大。
- 价：**0.6 元/秒，50 秒免费额度**（`wanx2.1-vace-plus` 0.70 元/秒，同额度）。
- 实测效果：替换后产品形态/比例/logo 对齐、**融合自然**（握持手指边缘、光影、透视都合理），
  画面其余内容保持不变 ✓

## 配音 + 口型

| 模型 | 需要什么 | 价格 |
|---|---|---|
| **`videoretalk`**（声动人像）✅ 首选 | 人物视频 + 人声音频（做口型替换） | **0.08 元/秒**（1800 秒免费额度）→ 5s≈0.4 元 |
| `wan2.2-s2v` | `input:{image_url, audio_url}` 静态图 + 音频 → 说话视频 | 480P 0.5 / 720P 0.9 元/秒 |
| `pixverse/pixverse-lipsync` | 视频 + 音频 | 0.12 元/秒 |

## edge-tts 本地配音（零 token、零 API 费）

- 二进制：`~/.hermes/hermes-agent/venv/bin/edge-tts`（`--list-voices` 过滤 `zh-CN` 有 8 个音色）。
- ⚠️ **`--rate` 必须用等号形式**：`--rate=+10%` ✓；`--rate "+10%"` ✗（直接非零退出，报参数错）。
- ⚠️ **偶发 `NoAudioReceived`**（网络抖动）→ **逐句生成 + 重试 3 次 + 校验产物 >2KB**，不要一次成句全挂就放弃。
- **逐句生成 → ffprobe 量每句时长 → 据此写 SRT**，比事后对齐字幕准得多（本项目 5 句 = 14.35s，正好压 15s 规格）。
- 男声 `zh-CN-YunxiNeural`（配男士出镜）/ 女声 `zh-CN-XiaoyiNeural`；语速 `+10%` 左右适合 15s 硬广。

## 欠费自查（省得白等）

- 欠费完整报错：`Arrearage Access denied, please make sure your account is in good standing`。
- **空 input 探针**（不计费）区分三态：`Model not exist` = 模型名错；`The product is not activated` = 未开通；
  `InvalidParameter …required field…` = 平台放行（不欠费）；`Arrearage` = 欠费。
- 欠费不等于停工：**配音、字幕、花字、对比片合成全部本地免费**，先把这些做完再等充值。

## 交付到飞书（脚本分工）

| 内容 | 脚本 |
|---|---|
| 视频（mp4） | `~/.hermes/scripts/feishu_send_media.py <mp4> "说明"` |
| **图片**（对比图、刀头特写） | `~/.hermes/scripts/feishu_send_image.py <jpg> "说明"`（走 `im/v1/images` + `msg_type=image`） |
| **任意文件**（配音 mp3、SRT） | `~/.hermes/scripts/feishu_send_file.py <file> "说明"`（走 `im/v1/files` + `file_type=stream` + `msg_type=file`） |

判断成功看返回 `code == 0`（打印机里就是 `0 success`）。
微信只用来回文字结论，成片一律走飞书（微信媒体会被 iLink 限流静默失败）。
