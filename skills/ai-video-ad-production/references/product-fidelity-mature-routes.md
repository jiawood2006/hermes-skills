# 产品保真：什么时候该「停手换路线」，别再改 prompt（2026-09-18 调研 + 实跑）

## 0. 触发与铁律（用户原话驱动）

用户在连续两轮「改 prompt → 重跑 → 又出问题」之后纠正：

> 「这么反复的修不是办法，要去找找网上有没有成熟的方案和经验技巧」

**铁律**：同一类产品缺陷（刀网颜色/纹理、形态、尺寸、接口位置、镜像重影、logo 乱码）
**改 prompt 重跑 2 次仍不根治 → 立即停手**，不要在 prompt 上继续加词。转做三件事之一：

1. **换路线** —— 让产品像素**不经过 AI**（官方图动效 / 视频编辑换真机）
2. **换引擎** —— 同 prompt 同参考图横评（`compare_video_models.py`）后再定
3. **换输入** —— 参考图裁切/顺序/机位要求（例如禁"机头正对镜头"）

"再调一版试试"是这条路里**最贵的动作**：每次 3-10 元 + 5-15 分钟，且**常把已通过的镜带崩**。

## 1. 行业共识（有出处，不是印象）

- **人人都是产品经理《2026 用 AI 做电商视频：稳定出片前的 8 个坑》**
  （https://www.woshipm.com/ai/6404293.html ，2026-05）：
  - 核心命题：「**电商 AI 视频真正难的，不是让画面动起来，而是让商品稳定地出现在每一个镜头里**」
  - 「电商视频首先是**商品片**，不是创意片」
  - 可落地三条：① **每个镜头写"商品锚点"**（不要在全局锁里写一次就完事，后面镜头只写动作 → 商品必漂）；
    ② **动作要有顺序+目的+停顿**，并在**商品最清楚的位置短暂停一下**（用户要看清）；
    ③ **机位必须服务商品**，否则"画面很好看，商品没看清"
  - 虚词要转成可拍的具体（"显瘦"→ 某动作下的肩线/侧面轮廓），这条对硬件产品同样适用（"轻巧"→ 手持时的占比与手指关系）
- **智源社区/知乎 ToB 视频调研**：B 端电商**普遍不用自由生成类视频**，用"质量可控、能快速大量生成的
  **数字人 / 混剪 / 相册类**"，因为要求"真实还原商品、卖点可控、时长可控"。
- **ComfyUI 官方有对口工作流**：`Product Scene Transformation`（Nano Banana Pro + **Wan VACE 2.1**，
  上传产品视频做场景转换）与 `Wan2.1 VACE Reference-to-Video`；社区口碑"完美解决一致性"。
- **Wan VACE 的核心价值**：它是**可控参考/编辑**模型（reference + control），不是自由生成 →
  这正是"AI 画场景、产品像素可控"这条路的技术底座。

| 路线 | 具体能力 | 产品保真 | 前置条件 |
|---|---|---|---|
| **① 视频编辑换真机** ⭐最对症 | 百炼 `wan2.1-vace-plus` / `wan2.7-videoedit`：**把已生成镜头里的产品替换成真机**（catalog 原话"比 prompt 约束彻底"）| 理论 100% | 自研模型，**免开通**（本账号可调，待实跑）|
| ② 换引擎做参考生视频 | `pixverse/pixverse-v6-r2v`（多主体参考 2-7 图，官方文档点名"电商产品特写"，720P 0.27-0.36 元/秒，最便宜）· `vidu/viduq3-ad_reference2video`（广告专用、声画同出、口型同步）· `kling/kling-v3-omni`（参考生视频 + 主体元素，prompt 里用 `<<<element_1>>>` 引用）| 中高 | 第三方模型需在百炼控制台「模型广场」**开通** |

| ④ 本地 ComfyUI + Wan VACE ref2v | 官方可控参考工作流 | 高 | 需 GPU（Mac 本机算力不够 → 得云 GPU）|
| ⑤ 海外（Runway Gen-4.5 References / Veo / Sora）| 物件一致性口碑最好（Gen-4 References 官方就是主打 object consistency）| 中高 | 海外网络 + 外币 + 投放端 AI 标识合规 → **只当审美参考** |

**组合建议**：人物/生活场景镜交给 AI（保留生活感）；**产品出现镜走 ① 或 ③**（产品必须 100% 真）。

## 4. 已实跑有效的做法（可放心复用）

### 4.1 官方真像素「刀网插入镜」（100% 真，0 API 成本）
```python
# 源：~/Desktop/电商素材/剃须刀/拉页图/拉页图-7.jpg（官方刀网微距，饱和香槟金+菱形放射网格+宽黑环）
side = 0.72 * W      # ⚠️ 0.80 会把上方那行「…0.1mm，短硬胡须深层剃净」文案裁进来
crop = im.crop(居中于 (0.50W, 0.415H), side)     # 裁成正方形 → 1080×1080 → 贴到 1080×1920 深黑底(y=420)
# 2s Ken-Burns（先放大再 zoompan，避免抖动）：
# scale=1620:2880,zoompan=z='min(1+0.0017*on,1.10)':d=60:s=1080x1920,fps=30,format=yuv420p
```
生成的 2s 片段**没有音轨也没问题**：装配时一旦给了 `vo`（整条旁白），`assemble_r2v_overlays.py`
会跳过所有段内音频链，只映射旁白。用 `make_ad.py` 的 `assembly.order[{file:…}]` 直接插进成片。

### 4.2 已验证的边界
- 参考图本身没问题：`mesh_gold.jpg` 是**饱和金**（已核）；但**镜前白光场景会把刀网洗成浅金/银金**——
  改 prompt 只能收敛到这里，**根治要靠 ①/③**。
- 一次提交**只能用一个 `duration`**：5s 段与 10s 段要拆成两个项目配置分别跑（runid 也要错开，否则 tasks json 互相覆盖）。
- `--steps plan` 免费且必跑：先审产品锁+分镜，再花钱提交。

## 5. 产品锁的四个高频缺口（都已写进 `templates/product_lock_head.txt`）

| # | 症状 | 成因 | 锁里怎么写 |
|---|---|---|---|
| 1 | **机头变成比机身宽的大圆盘/蘑菇头** | 分镜里出现"机头正对镜头/端详刀网"**必发生** | 【机头与机身】：直径与机身相同、连成等粗直筒、禁圆盘/蘑菇/飞碟/喇叭；**不要拍机头正对镜头**，最多侧前方 3/4 视角 |
| 2 | **镜中重影 / 第二张脸 / 多一个人** | 镜面场景太高频，模型自由发挥 | 【镜子】：倒影必须是**同一人的正确镜像**（五官/眼镜/衣服/姿态/位置全对应），禁第二张脸、重影、叠影、错位倒影、多余半张脸、倒影里多出的手/物 |
| 3 | **产品太小（小到看不清）** | 只写"≤ 画面高 1/6"会过头 | 【尺寸下限】：**不小于画面高 1/8**；手持镜里机身≈手掌长 1.1-1.3 倍；刀网必须清晰可辨 |
| 4 | **机身 logo 乱码/变形** | 小字高频翻车 | final_lock 写死：**只许一次干净的白色 Haier，禁乱码、重复、变形、看不清的文字** |

另：**镜子场景能避就避**——把"玄关装包"这类场景明确写成"**画面里不要出现镜子**"，比事后修重影便宜得多。

## 6. 验收清单（本轮就是在这一步漏了镜子才被打回）

- [ ] **必须先看整帧**（不要只放大产品）：镜子区域、有没有第二张脸/重影、有没有文字乱码、有没有人直视镜头
- [ ] 产品区域 2 倍放大：`product_fidelity_zoom.py --box=l,t,r,b`
      —— **默认 box 经常框不到产品**，按该帧产品实际位置改 box（或直接裁左下/中部再放大）
- [ ] **面积占比落在 1/8 ~ 1/6**：超过被投诉"产品太大"，低于被投诉"产品太小"，两个方向都真实发生过
- [ ] 用户只给截图不给时间码时：先 `locate_reported_frame.py <成片…> <截图>` 定位到秒，再抽该帧放大核
- [ ] 修完一段要**整片重核**：同一段素材同时用在 6 条变体 + 主片里，改一处要重跑全部引用
