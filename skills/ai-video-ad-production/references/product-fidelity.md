# 产品保真总纲（产品锁 / 尺寸比例 / 结构保真）

**管什么**：产品在成片里"像不像真机"的全部规则 —— 路线选择与停手判据、产品锁措辞、尺寸与长径比、结构（接口／按键／刀网／logo）保真、参考图纪律、官方真像素插入镜、核验方法。
**什么时候读**：只要镜头里会出现产品，开工前先读本文件；任何改动（换引擎、换分辨率、改分镜、改参考图）之后必须重读一遍。

## 1. 当前口径（2026-09-18/19 定，与任何旧文档冲突以本节为准）

- **产品镜引擎 = `wan3.0-video`**：字段 `input.images`（URL 列表）+ `parameters.watermark=false`；项目 JSON 写 `"model": "wan3.0-video"` 即切换。纯人物戏可用 `kling/kling-v3-omni`。
- ⚠️ `wan3.0-video` 用 `input.images` 时**把参考图1 当画面首帧**。要控开场就换图1（要"开场就是他本人"→ 图1 放男主图；代价 = 少一个金色校准锚点、刀网金色有变浅风险，换完必须重核刀网）。抽帧核验**必须含首帧 0.2~0.5s** —— 只看中后段会完全漏掉这类系统性问题。
- **生成一律 720P**；成片由装配器升到 **1080×1920**（字幕/花字/参数条/CTA 本来就在 1080 画布上渲染，`scale=1080:1920`，0 成本）。
- **真机机头 = 向上拱起的金色球面网罩**（穹顶状）＋外圈宽黑环；**不是平盘、不是平的黑色盖子、不是银白盘**。
- **手持时 机身总长 ≈ 手掌长的 0.7~0.8 倍**（比手掌略短、约一根食指长）；**绝不许比他的手掌还长**（画长了就变成保温杯／水杯）。
- **产品在画面里的占比 = 1/8 ~ 1/6**（特写镜不超过 1/4；下限不小于 1/8，别小到看不清）。
- **产品画不像的终极解 = 官方真像素插入镜**：`scripts/build_official_product_insert.py`（0 API 成本）。
- **整机入口 = `scripts/make_ad.py`**（六步 `plan / submit / fetch / verify / assemble / deliver`）；**锁模板 = `templates/product_lock_head.txt`**；**分镜正文 = `project.json` 的 `segments`**。
- **视频里不放价格**（画面与配音台词都不放）；尺寸重量类参数条（74×39mm / 70g / Type-C）可留。
- ⚠️ **禁走贴图 / 合成路线**（用户明确否决），场景必须原生。

❌ 已作废（2026-09-18/19）：`wan2.7-r2v` 当产品镜主力 / 原生 1080P 生成 → 现口径：产品镜走 `wan3.0-video`、一律 720P 生成、装配升 1080。
❌ 已作废（2026-09-19）：手持「机身总长 ≈ 手掌长 1.1~1.3 倍」 → 现口径：**0.7~0.8 倍**。

### 2.3 结构保真：接口/按键位置必须从官方图核对

AI 会把产品的**结构性细节按常识乱放**，即使外观、颜色、logo 都已正确。实测：真机 Type-C 在机身底部端面（与电源键同一面、旁边一个小指示灯），模型把充电线插到**机身侧面** ✗ → 用户直接指出「真机是底部有 type-C 充电口，不是侧面」「又是侧面充电」。

**做法**：①打开官方图逐条答完：接口在哪一面？按键在哪一面？哪一面是刀头？哪一面有 logo？侧面/背面有没有开孔？②拼网格逐张看图确认；③**写进 prompt 写死**，正反两面都写：「结构约束：Type-C 充电口在【机身底部端面】（与电源键同一面），机身左右两侧光滑、绝对没有充电口或任何开孔」；④充电镜头还要给**朝向条件**：「剃须刀【侧躺在柜面上、底部端面朝向镜头】，Type-C 线从底部充电口接入，底部指示灯亮起蓝色微光」。

**充电口的三种写法实测**：

| 写法 | 实测结果 |
|---|---|
| 机器**立在**柜面上，只写「Type-C 线从底部端面接入」 | ✗ 端面朝下看不见 → 模型自己编了个**侧面插口** |
| 机器侧躺 + 写「线从端面接入」但**没写线的走向** | ✗ 线**垂直插在圆柱侧面**上（缩略图看着还行，放大 3 倍才露馅） |
| 机器侧躺＋端面朝镜头＋**线沿机身轴线从端面直着往外**＋端面是**平的圆面不是圆头** | ✓ 一次通过 |

**有效措辞（照抄）**：「它侧躺在柜面上：机身水平、朝向镜头这一端是它的底部端面（**平的圆端面，不是圆头、不是圆弧收口**：中间圆形电源键、下方横向 Type-C 插口、旁边小指示灯）；Type-C 线沿着机身轴线从端面的插口插进去 —— 线从端面直着往外延伸、和机身在同一条轴线上，**绝不是从圆柱侧面斜插**；端面指示灯亮起蓝光；**机身的长侧面是光滑的、上面没有任何接口或按键**。」
**验收**：抽帧后**放大 3 倍**看插头落点（能看见平圆端面 + 线沿轴向 = 对）；**不要在缩略图上判断**。

## 3. 路线：什么时候该「停手换路线」

用户原话：「**这么反复的修不是办法，要去找找网上有没有成熟的方案和经验技巧**」。

**铁律**：同一类产品缺陷（刀网颜色纹理 / 形态 / 尺寸 / 接口位置 / 镜像重影 / logo 乱码）**改 prompt 重跑 2 次仍不根治 → 立即停手**，不要在 prompt 上继续加词。转向三选一：

1. **换路线** —— 让产品像素**不经过 AI**（官方真像素插入镜；或可控编辑把产品替换成真机）
2. **换引擎** —— 同 prompt + 同参考图横评（`scripts/compare_video_models.py`）后再定
3. **换输入** —— 参考图裁切/顺序/机位要求（如禁"机头正对镜头"）

⚠️「再调一版试试」是这条路里**最贵的动作**：3-10 元/次 + 5-15 分钟，且**常把已通过的镜带崩**。

### 3.1 引擎与分辨率执行规则

- 产品出镜的镜头**默认 720P**（0.6 元/秒，本来就比 1080P 便宜）。
- **任何分辨率 / prompt 改动后，必须重跑「逐镜 2 倍放大核产品 5 项」**。实测：同一角色、同一套 prompt，**只把 `parameters.resolution` 从 720P 改成 1080P、别的一字未动**，产品就崩了 —— 长径比 1.82~1.97 → **≈1.25 矮胖罐/"易拉罐"**；顶部浅金色蜂窝网 → **退化成深灰平盖**。"没动产品相关内容"**不构成**跳过核验的理由。
- 别为"更清晰"盲目升 1080P：用户给的标杆样片实测只有 **544×960**，真实感来自拍法（方向性实用光/真实皮肤/抓拍），**不是像素**。
- 一次提交**只能用一个 `duration`** → 5s 段与 10s 段要拆成两个项目配置（两个 runid）分别跑，否则 tasks json 互相覆盖。
- `--steps plan` **免费且必跑**：先审产品锁 + 分镜，再花钱提交。
- 引擎字段：`wan3.0-video` → `input.images`；`wan2.7-r2v` → `input.media:[{"type":"reference_image","url":...}]`。第三方（换引擎时用）：可灵 → 必须 `kling/kling-v3-omni-video-generation`（`kling-v3-video-generation` 不支持参考生视频），`media:[{"type":"refer"}]` + prompt `<<<image_1>>>` + `negative_prompt`；PixVerse → `media:[{"type":"image_url","url":...,"ref_name":"剃须刀"}]` + prompt `@剃须刀 `；Vidu → `media:[{"type":"image","url":...}]` + `parameters.size:"1080*1920"`（不传就出横屏 1914×1084）。
- 各家容易画错的方向：可灵 → 顶部成"凸起金圆盘/蘑菇头"；万相 → 帧间漂移（矮罐↔方柱）、齿状刀头；Vidu → 矮胖罐+小金凸顶。

### 3.2 已否决（作废）的路线 —— 见到这些做法，停，别执行

❌ 已作废（2026-09-16）：官方图 Ken Burns / zoompan 缓慢推近当产品镜 → 用户「把贴图运动起来的」「像 PPT」。
❌ 已作废（2026-09-16）：抠图透明 PNG **合成卡**（产品卡／水洗卡／参数卡，叠到 AI 背景）→ 用户「这种又成贴图了」「**我不要这种贴图的**」。即使 alpha 修干净、加阴影加颗粒，仍一眼识破。
❌ 已作废（2026-09-16）：AI 出人/场景 + 产品卡贴片按时间轴拼 → 同因被判贴图。
❌ 已作废（2026-09-16）：AI 首帧法 + `wan2.7-videoedit` 产品贴回 → 用户「产品很多细节都失真严重，越做越差」。
❌ 已作废（2026-09-18）：「不要走官方物料/合成类动效」当交付路线（整片走官方物料/合成卡） → 现口径：官方真像素**插入镜（3s）**是产品镜终极解；但整片贴图/合成路线仍**禁走**，场景必须原生。
❌ 已作废（2026-09-16 台账）：`SKILL.md`「产品特写别交给 AI —— 用官方真机图做 Ken Burns 推近」；路径②「素材拼接」当**交付**用（只可作草稿）；`scripts/compose_official_material_ad.py`、`make_comp_cards.py`、`cutout_product.py` 作交付路线（留作技术参考，抠图 alpha 必须先消毒）。

**根因（为什么贴图必被抓）**：产品像素不是**该场景渲染出来的** —— 光影方向、透视、手部接触关系必然自洽不了；修 alpha／加阴影颗粒只是"更不容易被发现"，不是解决。
**正解姿势**：产品身份由参考图锁定，模型**在场景里把它画出来**（手持、贴脸补剃、水龙头下冲刷、插线充电、塞进包里全部光影自洽）。代价：细节（网孔纹理、logo 字母）会轻微漂移 —— **用户已明确接受**（原话「代价：产品细节是AI画的，会轻微漂移」）。

⚠️ **元规则（用户纠偏）**：「**为什么别人能做的很好，要找思路找技能找方案**」—— 遇产品保真/口型/运镜这类**业界已有成熟解法**的问题：①先翻本技能 references ②再搜业界现成路线 ③然后才动手；**禁止自己手搓合成/贴回反复迭代烧预算**。

## 4. 产品锁：`templates/product_lock_head.txt`

- **用法**：`make_ad.py` 把模板里的 `{{字段}}` 用产品档案（`product_profiles.json` 的 `video_lock` 段）填进来，再和分镜脚本（`project.json` 的 `segments`）拼成最终 prompt。**`{{字段}}` 的值写在档案里，不要写在模板里**（这份模板所有产品共用）。
- **图1..图N 的顺序必须与 `project.json` 里 `refs` 的顺序一致**（`make_ad` 会打印顺序供核对）。
- 模板里每一句都是踩过坑之后加回来的（占比过大／长径比被拉长／刀网金色掉／充电口画到侧面／人物长胡子／直视镜头"太假"）；**删任何一句都可能让已通过的镜退化**。调过很多轮的措辞**不要手写**，必须走模板。

### 4.1 锁里的关键条款（照抄）

```
【产品在画面里的尺寸·最高优先级】{{size}}
【尺寸下限·别小到看不清】产品不能小到看不清：机身长度不少于画面高度的八分之一；
在"手持"的镜头里，机身总长大约等于他手掌长度的 0.7~0.8 倍（比手掌略短一点、约一根食指长），
也绝不许比他的手掌还长（画长了就会变成保温杯／水杯）；刀网（黑环＋金色球面网罩）必须清晰可辨，不能缩成一个小黑点。
【机身长度·用尺子量】{{length_rule}}
【机头与机身·最高优先级】机头（黑色环带＋向上拱起的金色球面网罩）的直径与机身直径相同（相等或略小），
机身与机头连成上下等粗的一根直筒；机头顶上必须是拱起的金色球面网罩，不是平的黑色盖子、不是银白盘；
绝不是比机身更宽的大圆盘、蘑菇头、飞碟形、喇叭形；
不要拍"机头正对镜头"的特写（实测那样必被画成宽圆盘）——最多用侧前方 3/4 视角，让画面里同时看得到机身侧面与刀网边缘。
【外观颜色·最高优先级】{{color_lock}}  【构图】{{lens}}  【光线】{{light}}  【皮肤】{{skin}}
【场景】每个镜头按文字里写明的地点与情景拍，不要换地点。  【服装】全程{{wardrobe}}，不要换衣服。
【人物】全程没有人直视镜头（生活抓拍感）：眼睛看向手里的产品、斜下方或环境，绝不看向镜头方向；
在镜子前的镜头里要侧一点脸、看镜中的自己；全程不说话、不做口型、不面对镜头念台词；做具体的事、有生活化的反应与表情变化。
【再次强调·最高优先级】{{final_lock}}
画面中不要出现任何文字、字幕、水印、乱码文字、价格、其他品牌logo。{{forbidden}}
```

**镜子条款（最高优先级）**：如果画面里有镜子 —— 镜中倒影必须是**同一个人的正确镜像**（同样的五官、眼镜、发型、衣服、姿态；位置、朝向、大小都要与真人严格对应）；**绝对不要出现第二张脸、第二个人、重影、叠影、错位的倒影、多余的半张脸**；倒影里**不要多出手、多出物体**；镜面本身要干净（不要有水珠、雾气、碎裂、重影造成的花屏）。

### 4.2 产品锁的四个高频缺口

| # | 症状 | 成因 | 锁里怎么写 |
|---|---|---|---|
| 1 | 机头变成**比机身宽的大圆盘／蘑菇头** | 分镜里出现"机头正对镜头／端详刀网"**必发生** | 直径与机身相同、连成等粗直筒、禁圆盘/蘑菇/飞碟/喇叭；**不要拍机头正对镜头**，最多侧前方 3/4 视角 |
| 2 | **镜中重影／第二张脸／多一个人** | 镜面场景太高频，模型自由发挥 | 倒影必须是**同一人的正确镜像**（五官/眼镜/衣服/姿态/位置全对应）；禁第二张脸、重影、叠影、错位倒影、多余半张脸、倒影里多出的手/物 |
| 3 | **产品太小**（小到看不清） | 只写"≤ 画面高 1/6"会过头 | **同时写下限**：不小于画面高 1/8；手持镜机身总长 ≈ 手掌长 **0.7~0.8 倍**；刀网必须清晰可辨 |
| 4 | **机身 logo 乱码／变形** | 小字高频翻车 | final_lock 写死：**只许一次干净的白色 Haier，禁乱码、重复、变形、看不清的文字** |

另：**镜子场景能避就避** —— 把"玄关装包"这类场景明确写成"**画面里不要出现镜子**"，比事后修重影便宜得多。

### 4.3 强化锁（hard lock）：标准锁压不住时用

写实化/加情景会让 prompt 变长，把标准 HEAD 段里的产品约束**稀释掉** → 在 prompt **最前面**再压一段"最高优先级"，把约束写成"违反即错误输出"，并给足**反面清单**（模型会滑向离它最近的错误形态）：

```
【最高优先级·产品一致性】画面里那台剃须刀必须和图1、图3完全相同：
①细长直筒，总长约为直径的1.9倍（≈成年人手掌宽度的0.9倍），绝不能画成矮胖的易拉罐／保温杯／杯子／药瓶；
②顶部必须有一圈浅金色蜂窝编织刀网（金黄色、细密六边形网）清晰可见——不是黑色、不是深灰、不是平盖、不是梳齿、不是光滑圆盘；
③机身灰黑色哑光、上下等粗、无收腰无台阶；④机身正面下方 Haier 白色英文只出现一次；
⑤机身正面和左右两侧完全没有接口、开孔、按键；⑥Type-C 充电口只在机身底部端面（图3）。
```

配套再加一句**占幅约束**：「**产品不要占满画面，占画面高度不到三分之一**」—— 产品在画面里占得越大，模型越容易自己"补"出错误的形状与网面纹理。
⚠️ 这段模板写于 2026-09-17，其中②的"蜂窝编织"已被更新、①的"手掌宽度 0.9 倍"与尺寸口径不同 → 照抄时：②改为**香槟金色放射状网格＋向上拱起的金色球面网罩**；尺寸倍数以现口径 **0.7~0.8 倍手掌长**为准。

**尾部重申（加情景 ⇒ 必须加）**：prompt 变长会稀释产品锁（实测加情景文字后金网从正确变浅金/银白、长径比 2.03→1.58）→ 在**产品锁后面（prompt 尾部）**再写一段「【再次强调·最高优先级】产品必须与图1/图2完全一致：饱和香槟金放射网格＋明显黑环＋枪灰金属直筒，总长≈直径1.85倍；**任何一帧都不许变形、变色、变胖、拉长**」——**尾部指令权重高**。

### 4.4 A/B 归因：一次出片完成隔离

怀疑"是分辨率还是 prompt 导致的失真"时，**不要一轮一轮试**：同一角色**同时**提交**只差一个变量**的两版（例：标准锁 × 720P vs 强化锁 × 720P），13 分钟一次拿到归因，还顺手得到一版可用成片。对比时只比**同一机位、同一时段**的帧。提交脚本按 `runid = 角色_分辨率[hard]` 命名任务与产物文件（如 `m_720p` / `m_720ph` / `o_720ph`），否则并发跑两版会互相覆盖 tasks json 和 mp4。

## 5. 尺寸与比例

### 5.1 排查顺序：先「占画面高多少」，再「长径比」

用户说「产品太高了／尺寸不对太长了／太大了」时，**先量再改，别猜**，而且往往**两层都有**：

| 层 | 实测 | 修法 |
|---|---|---|
| ① 机身长径比 | 示例镜 **2.45**（真机 1.93，长 25%） | 「上下等粗的**直筒圆柱**、总长≈直径 **1.85** 倍」＋「**机身总长 ≈ 机头直径的 1.9 倍**（超过 2.5 倍就是画错了）」＋「五指合拢、**手掌盖住机身一半以上**」 |
| ② **在画面里显得太大**（更致命、更易漏） | 该镜**整机占了画面近一半高** → 观感 = 保温杯；真机只有 70mm、比成年人手掌还短 | 见「显小三条」 |

### 5.2 「显小三条」（只写否定式约束会被无视）

1. **物体身份**：「**这是一台 70 毫米长的迷你剃须刀，比成年人手掌还短**」。
2. **可自检的数字**：「产品出现在画面里时**整机长度不超过画面高度的六分之一**（特写镜也不超过四分之一）」。
3. **机位**：该镜**退成中景**（画面里能看到上半身＋镜子＋洗手台），机器拿在胸前、**不凑近镜头**。负面词只作辅助保留：「绝不许拍成保温杯／易拉罐／大水杯那么大的东西」。

**必须「措辞 ＋ 景别」同时改**：只加「用机头直径当尺子」的措辞**不够**（v18 加了尺子仍然 ≈2.4，当场被连问两次）。v19 三条一起上才过：长径比 **1.93** ＋ 整机只占画面高 **≈20%** ⇒ 用户端「太高了／太长了」消失。**只用②不用③ ＝ 白花一轮。顺序：先景别，后措辞。**
→ **改完要用标尺量画面占比验收**。

### 5.3 长径比措辞敏感度表（同一套参考图，只改措辞/机位）

| 措辞 | 机位 | 实测长径比 | 判定 |
|---|---|---|---|
| 「细长小圆柱，长约直径 **2 倍**」 | 竖举到脸前、占满画面 | **2.56** | ✗ 用户判「高度有点高了」 |
| 「细长直筒、总长≈直径 **1.9 倍**」 | 侧面拍摄、整根可见 | **2.03** | ○ 过检 |
| 「**短圆柱**、总长≈直径 **1.8 倍**」 | 斜握胸前（不俯拍） | **1.58** | ✗ 偏胖 |
| 「**上下等粗的直筒圆柱**、总长≈直径 **1.85 倍**」 | **镜头与产品齐平、侧面稍低（禁俯拍）** | 1.7~2.2（遮挡校正后 ≈1.9） | ✓ v17 交付 |

真机基准 **1.93**。
→ 措辞用「**上下等粗的直筒圆柱** ＋ 总长≈直径 **1.85** 倍」＋人体锚点（「直径 ≈ 他两根手指并拢」「手掌能包住机身中段」）。**不要写「细长」**（模型会拉长），**也不要写「短圆柱」**（模型会压胖）。

❌ 已作废（2026-09-17）：写「**短圆柱**、总长≈直径 **1.8** 倍」 → 实测过冲到 **1.5~1.7（偏胖）**；另「细长…约直径 2 倍」→ 2.03~2.56（偏长）。
❌ 已作废（2026-09-17）：prompt 里写「细长」或「短圆柱」 → 现口径：只写「上下等粗的直筒圆柱、1.85 倍」＋机位兜住。

### 5.4 「看着大 / 看着胖」的根因与修法

| 根因 | 实测 | 修法 |
|---|---|---|
| ① **直径胖**（不是长度长） | 长÷掌宽 = 0.91 ✓ 达标，但**直径÷掌宽 = 0.63**（真机 0.46）→ 长:径只有 1.45（真机 1.9）→ 像"胖杯子" | 锚点改成「**粗细 ≈ 他两根手指并拢的宽度**」（真机 39mm ≈ 2×19mm）＋「长:径≈1.9」＋「绝不是保温杯/易拉罐/咖啡杯」 |
| ② **构图太近** | 说明写「中景/产品很小」模型也照样怼特写（水洗动作天然吸引模型聚焦产品） | 明写「**产品长度不到画面高度的八分之一**」＋「能看到他的上半身、水龙头、洗手台」→ 实测产品降到**画面高度 1/22** |
| ③ **机位比文字更管用** | 同一 prompt：**正面/仰角机位 → 机身被压成"矮胖罐"（长:径 1.28）**；改成侧面后回到 **1.9~2.4** ✓ | 手持特写必须**从侧面拍**（画面里能看到整根机身的完整长度）；**俯拍会把机身压短**（1.58）→ 写「镜头与产品齐平、从侧面稍低处拍（不要俯拍）」。凡展示产品本体：**先定景别与机位，再改文字**；正面机位是"看着大/看着胖"的隐形元凶 |

**最有效的一招：加第 4 张参考图当"粗细视觉锚点"** —— 把官方实拍（拉页真人图）里**「真手握产品」的局部**裁出来（`crop` 掉人脸，只要手＋机身；避开画面上原有文字），作为 `reference_image` 传进去，prompt 写：「图4 = 官方实拍里真手握产品的局部，**只用来参照产品粗细**（粗细 ≈ 他手指宽 1.5 倍）；**不要抄图4的色调/背景/服装/构图**」→ 实测：文字锚点三轮压不住的"胖"，加这张后同段产品比例正常（长:径 ≈2.0）。

### 5.5 用「机头直径」当尺子（最有效的比例验收口径）

prompt 里写：**「机头（黑环＋金色球面网罩）的直径当尺子：机身总长 ≈ 机头直径的 1.9 倍（不到机头两个直径，超过 2.5 倍就是画错了）」** —— 机头是画面里最显眼的圆，模型能拿它自检；比「≈直径 1.9 倍」这种抽象说法有效。

### 5.6 口径一变 ⇒ 所有产品入镜的段一起重跑

一旦「产品显多大」的口径变了（或新定），用**同一套 HEAD 重跑所有产品入镜的段**（本项目 3 段 ×10s 并行 ≈ 15 分钟 / ≈ 18 元），交付前整片抽帧并排核一遍一致性，**一次交到位**。
理由：用户连否同一镜两次后全片抽帧发现，**另外两镜（车内取产品、床头充电）机器占画面约 1/3**，比被指出的那镜更离谱，只是他还没翻到 —— **按他的标准修好这一镜，下一镜必被同一条标准否掉**。

### 5.7 其它尺寸硬规则

- **机身被「拉长」**：prompt 写明「总长≈直径 1.9 倍」，模型仍按"电剃须刀 = 细长罐"的固有印象画（实测长径比 2.56，拉长 35%）→ 三条一起上才压得住：①写「**短圆柱**，总长≈直径 **1.8** 倍，≈他手掌宽度」②人体锚点「直径 ≈ 他两根手指并拢／手掌宽度的 0.5 倍」③**换机位**：竖举到脸前的镜头必拉长 → 改「**斜握在胸前、机头朝斜上方**，镜头从斜前方拍」。验收：拿帧数像素算长:径，落在 **1.6~2.1** 才算过。
  ❌ 上面的「短圆柱 1.8 倍」已作废（2026-09-17，实测偏胖）→ 现口径：**上下等粗直筒、1.85 倍**（见 §5.3）。
- **小尺寸产品的机头会「糊成一团」**：水洗镜里产品只占画面高度约 1/8 时，机头被画成深色块（看不到黑环与金网）✗ → 明确写「**机头朝上，黑色环带＋金色网罩清晰可辨、机身完整不糊**」，并给足尺寸（**约占画面高度六分之一**，别再缩到 1/10 以下）。
- **手持特写「别占满画面」的约束不稳定**：prompt 已写「占画面高度不到一半」仍拍到占满 ✗ → 更靠谱是把**机位写具体**（「中近景，他的手在画面下方三分之一处，产品竖直拿在胸前」），**别只写否定约束**。
- **跨镜头尺寸一致性**：分段生成时每段独立构图 → 模型在"产品感强"的镜头（冲洗/充电）里**自动把产品拍大**。HSQ1 实测：剃须镜产品 ≈55px（≈头高 1/3，符合真机 74mm ✓）；水洗镜 ≈170px、**手指合不拢、手掌包不住** → 视觉放大约 **2.5~3 倍** ✗。根治写法（三条都要加）：①**物理可容性**「握着时**手掌能整个包住机身、五指能合拢绕过机身背面**，机身只比他一根手指粗一点」（模型对"手能不能握住"远比对数値敏感）②**构图约束**「**中景，不要产品特写**；产品只占画面很小一部分，绝不能占满画面」＋负面词「不能变成保温杯/易拉罐/音箱大小；产品不能比手掌大；手指必须能合拢握住机身」③**特写镜头要单独出一段**，别和远景混在一条 prompt 里（同段既写远景又写特写，特写仍会被放大）。

## 6. 参考图纪律

### 6.1 每个「会被挑错的部位」都必须有参考图

根因（实测）：用户指出「充电口画在机身正面」时，**根因不是 prompt 写得不够，而是参考图里没有那一面** —— 只喂正面产品图，而 Type-C 口在**底部端面**，模型没见过只能凭空编，编到正面去了；改文案改了三轮都没用。
修法：把官方**底部视图**（`产品图/3.png`）裁成 JPG 当**第三张 `reference_image`**，prompt 补一句：「图3 = 同一台机器的底部视图：底部端面中间是圆形电源键，下方是 Type-C 插孔，旁边一个指示灯；机身正面与左右两侧没有任何接口或开孔。」→ 实测正面/侧面开孔归零 ✓、充电镜头接线落在底部端面 ✓。
→ **通用规则**：产品上任何一个「用户会挑错的部位」（接口 / 按键 / logo / 刀网纹理 / 粗细比例 / 底部端面）都必须有一张参考图能看见它；**看不见的部位，写多少文字约束都挡不住模型编**。

### 6.2 参考图集绝不能混入「形态错误」的图（污染）

实测：把一张 AI 图（人手持**齿状梳刀头＋细长机身＋圆钮**的错误产品）当第 3 张参考喂进去后，模型在冲突参考间摇摆 → 万相中景画成"推子"、可灵头顶长成"蘑菇头"、帧间漂移。
做法：人物参考图**必须裁到不含产品**（只留脸＋肩/发，去掉手和产品），或干脆不传人物参考图。上传后**回读校验**：`curl -o /dev/null -w '%{http_code}' https://yunvela.com/dh/<file>` 必须 200，再用 vision 确认画面里没有产品/手。

### 6.3 参考图硬限制与技术准备

- **每次最多 5 张可提交**（实测：产品正面＋真手全长＋刀网微距＋底部端面＋人物 = 一次通过）。
- 尺寸限制：宽高 **240~8000px**、宽高比 **1:8~8:1**、**≤20MB**。
- 电商抠图常见 **rgba 透明通道 → r2v 不支持**，必须拍平转 JPG：
  `ffmpeg -y -i 正面图.png -vf "scale=1400:-1,format=rgb24" -q:v 2 hsq1_ref.jpg`
- 产品图选**干净正视图**（无文字/无贴图/无促销标），白色或纯色背景。
- 托管：`scp xxx.jpg yunvela:/tmp/` → `sudo mv` 到 `/opt/yunvela-site/dh/` → `curl -s -o /dev/null -w '%{http_code}' https://yunvela.com/dh/xxx.jpg` 必须 200。
- `reference_voice`：公网 mp3、**时长 ≤10 秒**，超了直接 `InvalidParameter: duration should be at most 10s` 秒拒（实测 12.384s 被拒，改 8.7s 通过）。
- **每张参考图只放一个主体** —— 这是硬约束；每张入池前**逐张看图**。

### 6.4 当「比例参照」的参考图必须露出产品完整长度

实测：只裁产品上半截（下半截被手挡住）→ 模型照它把机身画成**短粗圆柱（长:径 1.25，真机 1.9）** ✗。
规则：任何当"比例参照"的参考图**必须露出产品的完整长度**，并在 prompt 注明「这张图里被手挡住的部位不用管；不要抄这张图的服装、背景、手势、色调」。修正版 = 官方拉页图里「手握着整机、从头到脚可见」的那一格（本案 `hand_full.jpg`）→ 长:径回到 1.8~2.03 ✓。

### 6.5 素材来源优先级（人物真实感 = 参考素材决定，不是提示词）

- **来源优先级**：客户官方物料（拉页图/详情页/宣传片里的真人）> 真实拍摄照片 > AI 生成图。
- 喂 **AI 磨皮人物图** → 输出**必然是 AI 脸**（皮肤光滑无毛孔、牙齿假白、网红精修）；提示词里写"真实肤质/不磨皮"＋负面"塑料感、过度磨皮、网红脸"**压不住**。实测换成官方拉页里的真人素材后，人物明显更真实（面颊结构、眉眼神态、胡茬细节都出来了）。
- 顺手一查：官方拉页里往往还有**真实使用场景照**（车载/办公/约会/出差）和**产品结构特写**，比我们自己造的素材强得多 —— **先翻客户物料，再考虑自己造图**。
- 官方素材检索顺序：官方拉页/主图/详情页的**真人素材**（客户自有资产，无版权风险、真实感最好）→ 再考虑 AI 生成。
- **出片前先过四关**（缺一关就会返工）：①**定型号**：打开发产品属性表 `产品属性/<型号>.xlsx`（最高优先级资料）②**排除污染图**：目录里可能混着别的型号的图 → 从属性表里的官方素材 URL 下载比对（字节数/哈希一致才算官方原图）③**写产品档案**：形制/比例/刀头/logo/按键位置逐项文字化 → `product-spec-extraction/references/<型号>-spec.md` ④**形制写进 prompt**：把 ③ 的几何段落**整段贴进生成 prompt，不能只丢参考图**。

### 6.6 人像参考图会「决定」胡子与表情 —— 视频 prompt 压不住

症状：成片里男主**长出小胡子、眉头紧皱**；在**视频** prompt 里写「上唇绝对没有胡须」「不要皱眉」→ **完全无效**。
根因：**生成候选图时就带上了**（旧候选 prompt 写了「淡淡胡渣」＋「抓拍感、不是看镜头的商业摆拍」，`wan2.6-t2i` 直接理解成**八字胡/山羊胡＋严肃皱眉脸**，4 张候选全中），视频模型照参考图复刻 —— **图能压住文字，文字压不住图**。
**铁律：人像参考图必须「干净＋带笑」**，候选 prompt 必须写死这几条（实测 4 张候选无胡须、眉眼放松、带笑、仍写实）：

```
真实摄影照片，半身人像，不是影棚商业模特照。
上唇必须完全光洁：上唇上方没有任何毛发、没有小胡子、没有胡子阴影；下巴和下颌也剃得干干净净。
下巴、上唇、下颌的肤色必须和脸部完全一致：是干净的肤色，绝不能出现发绿、发青、发灰的胡须阴影或色块。
看着镜头自然地笑：嘴角上扬、露出一点牙齿、眼睛因为笑微微眯起；眉毛放松舒展、不皱眉、不浓眉，眼神温和亲切。
看起来年轻：面部紧致、不超过30岁的样子，发量正常不秃。
半身构图：能看到肩膀和胸部以上，头顶留一点空间，不要只拍脸部特写。
皮肤是真实皮肤：可见毛孔、细纹、肤色不完全均匀；不要磨皮、不要塑料感、不要网红脸。
光线是室内自然光或真实实用灯，有明确方向、有明暗过渡与真实阴影，不要平光、不要打光板感。
背景是真实生活/办公空间（有生活道具、轻微杂乱），有景深虚化。画面中不要出现任何文字、水印、logo。
```
再各加一句设定（年龄/眼镜/衣着/在哪/在干什么）。
验收候选图：**逐张 2 倍放大只看三处 —— 上唇／眉毛／表情**，不合格就重出（1 分钟 1 张，别省）。
⚠️ **别在小缩略图/4 格拼图上判颜色**（色偏是缩放/JPEG 伪影），放大后再下结论。
⚠️ 参考图下巴的**青色胡影**会原样带进视频。
另：人物/拍法层的坑（旁白＋生活抓拍、暖色实用光、真实皮肤、每个镜头显式写地点）不属于本文，见 `scene-drama-and-candid-style.md`。

## 7. 官方真像素插入镜（产品镜的终极解）

**触发条件**（满足任一即换路线，不要再改 prompt）：①中景手持镜的产品形态**反复修不好**（本项目：两轮各换一种错法 —— 先"没有刀头的光筒"，后"保温杯"）②用户说"认不出是什么／不像真机／产品太小／刀网不对"，且已按锁改过 2 轮 ③投放素材要求"产品必须真实"（甲方红线）。
**依据**：用户定的「**同缺陷改 prompt 修 2 次不根治 → 停手换路线/换引擎**」。AI 生成的产品只适合"生活情景里的道具"，**产品必须被认出来的镜头交给真像素**。

### 7.1 片内结构（15s 变体）

```
[钩子 5s（AI，人物/情绪）] + [官方真机产品镜 3s（真像素，零 API 成本）] + [正片 7s（AI，截短）] = 15s
```
- 正片从 10s **截到 7s**：一是给官方镜腾时长，二是顺手避开原正片尾部的瑕疵镜（场景漂移、镜面花屏）。
- 官方镜放在 **5~8s**：正好卡在"钩子看完、正片开始"的位置，也是观众需要看清产品是什么的时候。
- **不要**把官方镜放到片尾（会和 CTA/参数条抢注意力）。

### 7.2 官方 3s 插入镜怎么做

脚本：`scripts/build_official_product_insert.py`（原 `/tmp/build_official2.py` 入库版本）。
内容 = 三个真像素特写，各 1s，缓慢推近（`zoompan z='min(zoom+0.0006,1.06)'`），之间 0.15s 交叉溶解：

| 镜 | 素材 | 处理 |
|---|---|---|
| 1 | `拉页图/拉页图-7.jpg` | **裁掉左侧中文文案与底部标注**（本项目用 `crop(118,480,556,1105)`）；只留金网＋深灰底 |
| 2 | `产品图/正面图_cropped.png` | **白底必须抠成透明**（否则贴上深灰底会露出白色矩形 ✗）；合成到深灰径向渐变底，产品占宽 ~0.62 |
| 3 | `产品图/3.png` | 先自动求**非白内容包围盒**定位端面，再按 9:16 裁 + 抠白底；展示电源键＋Type-C |

背景统一用**深灰径向渐变**（与拉页图-7 的深色背景一致），三帧色调才连贯。

**三个必踩的坑**：
1. **白底不抠 → 露出矩形**：官方产品图多是白底不透明 PNG，直接 paste 会在深色底上留下白色方块 ✗。做法：像素级把接近纯白的区域置透明、边缘按阈值羽化。
2. **官方图带中文文案/标注**：拉页图左侧有卖点文案、底部有参数标注 → 裁图必须避开，否则成片里出现乱码般的半截字 ✗。
3. **插入段必须带一条静音音轨**：装配器按段取音频流，**没有音轨的段会直接报错** ✗。做法：`ffmpeg -i official.mp4 -f lavfi -i anullsrc=channel_layout=stereo:sample_rate=44100 -shortest -c:v copy -c:a aac`。

### 7.3 接进 6 条变体的时间轴（关键：字幕平移 → 旁白自动重排）

插入 3s 后**所有 overlay 时间要整体 +3s**，否则字幕/花字/参数条会与画面错位。
- 规则：`start ≥ 5.0s` 的字幕/花字 → `start = min(start+3, 13.0)`、`end = min(end+3, 14.9)`；参数条锚到 `12.6~14.9`；CTA 落在末尾 1.5~2s 内即可。
- **旁白不用手工重做**：装配器的旁白轨由 `scripts/build_vo30.py` 按 `overlay_cfg.json` 里**每条字幕的 `start`** 逐句 TTS 排布 → **改字幕时间 = 旁白自动重排对齐** ✓。
- 官方段配一句**官方原文**旁白（本项目用「全新镀钛刀网，持久耐用更锋利。」），否则 5~8s 会出现 1s+ 无语音的空白。
- 官方 2s 片段**没有音轨也没问题**：装配时一旦给了 `vo`（整条旁白），`assemble_r2v_overlays.py` 会跳过所有段内音频链，只映射旁白；用 `make_ad.py` 的 `assembly.order[{file:…}]` 直接插进成片。

## 8. 核验

### 8.1 量产品比例：先用已知真值校准量法，再报数字

**血的教训**：用三种自动分割去量渲染帧的长径比，**全部给出与事实相反的结论** —— 报「1.55 正常」，而用户看的其实是 **2.45 太长了**。**不可信的测量比不测量更糟**（会把不合格判成合格）。

| 试过的做法 | 失败原因 |
|---|---|
| 暗像素阈值掩膜 | 手挡下半截**截短长度**、背景暗部**撑大直径** → 假值 1.49~1.71 |
| 泛洪填充（flood fill） | 种子落在背景上 → 整幅被填满，无意义 |
| 金色检测（R-B / G-B 判金） | **皮肤也满足金色条件**（R-B≈60、G-B≈20~40）→ 直径报成 832px |
| 自动配色测量（渲染帧） | 渲染的暖光会让"金色"判据命中皮肤/背景（实测整帧 59% 被判成金色 ✗）；深灰机身掩膜又被暗背景/手串掉 |

**可靠量法只有两条**：
1. **真机基准（可自动量、已验证）**：官方**白底**产品图 → 取非白像素包围盒 → 逐行宽度剖面。HSQ1 实测 `产品图/正面图.png` = **626×1207 ⇒ 长径比 1.93**，逐行宽度恒定 ⇒ **上下等粗直筒**。渲染帧要跟**这个数**比，不是跟印象比。
2. **渲染帧（不自动分割）**：与真机正面图**按同高并排**比对；或给帧叠 **5% 网格标尺**（洋红竖线/青横线＋百分比标签）后自己读「金网直径／全长」再换算。

工具：`scripts/measure_product_truth.py`
- `truth <白底官方图>` → 真机基准长径比 + 逐行宽度剖面（判等粗直筒）
- `grid <帧.png>` → 叠 5% 网格标尺的读数图
- `cmp <帧.png> <白底官方图>` → 同高并排对比图

**报数字前自检：这个量法在已知真值上跑过吗？** 没跑过就不要把数字写进给用户的结论。
**「画面占比」是最好的指标**（只要产品在画面里，直接读它占画面高的比例即可），优先用它验收。

### 8.2 交付前必查：逐镜 2 倍放大核产品 5 项

⚠️ **必须把每一镜的产品区裁出来放大 2 倍逐个核对，禁止只看小尺寸拼图。** 实测漏检：拼图每格仅 240~360px 时，**接口/logo 级错误根本看不见**。模型会一次错一种（用户一眼指出「充电口画在机身正面」「水洗镜头尺寸偏大」「网面成银色梳齿、机身变矮胖罐」）。

R2V 每镜独立生成 → 产品这几项**每镜都会重新漂**，交付前逐镜过一遍：

| 项 | 正确形态 | 模型常见错 |
|---|---|---|
| 充电口 | 只在**底部端面**（朝下那面） | 画到机身正面/侧面；底部多出一节带椭圆口的黑段 |
| Haier | **灰色机身正面下方，只印一次** | 印到黑色环/黑段上、上下各印一次、位置乱漂 |
| 外形 | **直筒圆柱**（长:径 ≈1.9:1），顶部黑环与机身**齐平同宽** | 收腰/台阶/锥形/矮胖罐（1.3:1）、黑环宽出一圈 |
| 刀网 | 外圈宽黑环 + **香槟金放射状网格 + 向上拱起的金色球面网罩** | 银色梳齿、平滑金盘、平的黑色盖子、放射状条纹（旧口径） |
| 尺寸 | 产品长 ≈ **手掌宽的 0.9 倍**（握住时手掌能整个包住、五指合拢能绕过背面）；**粗细 ≈ 他两根手指并拢**（直径÷掌宽 ≤0.5，真机 0.46）；**占画面高 ≤1/8（水洗/特写镜）、整体 1/8~1/6** | 偏大 1.2~1.5 倍（"拍成了保温杯"）；直径画粗 37% 变"胖杯子" |
| 眼镜（角色戴镜时） | 镜框**规整、左右对称、镜片不糊**；说话镜头过 videoretalk 后**要再核一遍** | 镜框塌陷/融进脸/单边缺失（AI 最易崩部件，缩略图看不出，必须 2 倍放大） |

这 5 条要**逐条写进 prompt 并带反面词**：「正面与左右两侧完全没有开孔」「只印一次」「无收腰无台阶无锥形」「不是银色、不是梳齿、不是平滑圆盘」「底部没有多余的一节黑色段」。
放大核对做法：`ffmpeg -ss <t> -i seg.mp4 -frames:v 1 -vf "crop=<w>:<h>:<x>:<y>,scale=iw*2:-1"` 逐镜看图。

### 8.3 验收清单

- [ ] **必须先看整帧**（不要只放大产品）：镜子区域、有没有第二张脸/重影、有没有文字乱码、有没有人直视镜头、**有没有白色矩形残留**
- [ ] 产品区域 2 倍放大：`scripts/product_fidelity_zoom.py --box=l,t,r,b` —— **默认 box 经常框不到产品**，按该帧产品实际位置改 box（或直接裁左下/中部再放大）
- [ ] **面积占比落在 1/8 ~ 1/6**：超过被投诉"产品太大"，低于被投诉"产品太小"，两个方向都真实发生过
- [ ] 逐镜 2 倍放大核产品 5 项（§8.2）；充电口放大 **3 倍** 看插头落点
- [ ] 抽帧肉眼比产品：**形状 / 颜色 / logo / 有没有变成别的型号**；拿帧数像素算长:径，落在 **1.6~2.1** 才算过
- [ ] **并排质检**（不能自己看一眼说像）：参考图 + 成片抽帧拼横向对比图 → 交 `vision_analyze`，按五项逐条问「①形制比例 ②颜色材质 ③刀头形状与颜色 ④logo 有无/位置 ⑤按键/接口」，输出"像／不像"。**「有点像」按不像处理**，不要自我说服。
  `ffmpeg -y -i ref.jpg -i p3_2.0.jpg -i p3_5.0.jpg -i p2_6.0.jpg -filter_complex "[0:v]scale=-1:640[a];[1:v]scale=-1:640[b];[2:v]scale=-1:640[c];[3:v]scale=-1:640[d];[a][b][c][d]hstack=4" -frames:v 1 compare.jpg`
- [ ] 全片网格与**官方产品图并排**逐帧比：`ffmpeg -i out.mp4 -vf "fps=1,scale=270:-1,tile=5x2" -frames:v 1 grid.jpg`
- [ ] STT 反查台词（`~/.hermes/scripts/voice_stt_local.py`）= 我们的文案；有无乱码文字水印
- [ ] `ffprobe` 分辨率/时长；官方插入段看产品是否完整（金网球面＋黑环＋机身＋Haier）
- [ ] **用户只给截图不给时间码时**：先 `scripts/locate_reported_frame.py <成片…> <截图>` 定位到秒，再抽该帧放大核
- [ ] 修完一段要**整片重核**：同一段素材同时用在 6 条变体 + 主片里，改一处要重跑全部引用
- [ ] 发飞书后**回读消息列表**确认送达（脚本回显 ≠ 送达）

⚠️ **抽帧时间轴别用 `fps=1/N` 抽样去判断**：抽样出的帧时间戳不可靠（实测按抽样误判"字幕错位"，用 `-ss` 精确抽帧复核后 6/6 全部对齐）。判断时间轴一律 `-ss <t>`。
⚠️ 其它脚本级坑：`ffmpeg` 解帧默认从 `_0001` 开始 → 加 `-start_number 0`；任务跟踪 JSON 要 `d.update(ids)` 合并不要 `json.dump({tag: tid})` 覆盖；`vstack/hstack` 输入尺寸不一致会 SIGSEGV(139) → 拼图改用 PIL；`fps=N,tile=5x3` 有时只出一帧/大量黑格 → 按显式时间点逐帧抽图 + PIL 网格拼接；`freezedetect` 测不出"静图+zoompan"（静止区间照样 0），是否"贴图感"必须靠肉眼/视觉复核。

### 8.4 画面里不许出现价格（三重反查）

用户原话：「**视频里面不要体现价格，因为价格经常变化**」。
- ✅ 参数条（`74×39mm / 70g / Type-C`，尺寸·重量·接口）保留 —— 这些不常变。
- ❌ 价格条（¥169）、价格花字、**配音台词里的价格** 一律删；做法：`overlay_cfg.json` 里删掉 `price` 键（`assemble_v12.py` 会自动跳过），15s 脚本里也要删 `ov_price.png`。
- 三重反查：①字幕/花字配置 json 里搜「¥ / 元 / 价格」②`voice_stt_local.py <旁白mp3>` 反查**配音里念的内容**（本项目删掉价格条后，最后一句台词「到手一百六十九」**还在配音里**，靠这一步才抓到）③整片抽帧拼图（30s 抽 7 帧 + 15s 抽 3 帧）肉眼确认画面无 ¥。
- 15s 版与 30s 版的**叠加层配置共用一份 json**：删价格项后两个版本同时生效，别只改一个。
- 15s 版可能跨段取镜（本项目 = seg1 ＋ seg3），重跑单个段时**别用 VER 自动推段名**，显式把段文件名当参数传进去，否则会去找不存在的 `v<N>_seg1` 而报 "No such file"。
