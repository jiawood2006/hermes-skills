# 逐镜返工的经济性 + 成片级交付验收 + 生成脚本工具坑（2026-09-17 全流程血泪）

> 配套阅读：`references/wan27-r2v-product-lock.md`（产品锁、尺寸锚、充电口、验收方法）。
> 本文件只讲**怎么迭代**和**怎么交付**：一次改一处还是全片重跑、成片级最后一道检查、写脚本的坑。

## 1️⃣ r2v 的返工粒度：一段 = 10 秒 = 3 个镜头

一次 API 调用生成**一整段**（10s，含 3 个镜），**没有"只重跑某一个镜头"的选项** ⇒ 改一处 = 整段重来（0.6 元/秒 = 6 元/段 + 约 15 分钟）。

**硬规则：**
1. **先定位**：把用户发来的截图与成片抽帧逐格比对，确定是**哪一段哪一镜**，再动手。**不要全片重跑**。
2. **已验收通过的段不要重跑** —— 重跑会把已经对的镜一起换掉。
   实测：seg3 的充电镜在 v21 已经画对（机器侧躺、端面朝向镜头、蓝灯），我为了"把机器收小"重跑 v22，
   结果 **端面朝向丢了、Type-C 又插回圆柱侧面** ✗✗ —— 一个已通过的核心项被自己弄丢。
   → 某段"有对有错"时，先判断重跑会不会把对的带坏；**宁可带一个可接受的小瑕疵交付，也别丢掉核心项**。
3. **允许混版交付**：最终成片可由不同轮次的段拼成（实测 v23 = seg1 来自 v20 + seg2 来自 v19 + seg3 来自 v23），
   每段各自验收即可；装配脚本按传入的段文件名拼，不必强求同一版本号。
4. **用户连发多条反馈时**：先一次性把问题**分类**（产品形态 / 尺寸占比 / 场景情景 / 机位 / 后期元素），
   能合并到同一轮重跑的合并（例如"加情景 + 修比例 + 去价格"一轮解决），别一条反馈跑一轮。

## 2️⃣ 成片级最后一道（逐段通过 ≠ 成片通过）

装配后**抽帧 9~10 格**（覆盖每句字幕、每个花字的起点）一次核完：

- [ ] 每句**字幕**文字正确、无遮挡、无错位
- [ ] 花字/参数条文字正确；**画面里没有任何价格**（用户硬要求「价格经常变化」：价格条已删，
      参数条只留尺寸/重量/接口）
- [ ] 右下角「**AI生成内容·广告**」合规标注在位
- [ ] 无乱码文字、无水印、无多余接口
- [ ] `ffprobe`：30s 版 = `30.000000`、15s 版 = `15.000000`、`1080×1920`
- [ ] 交付 = 覆盖桌面既有交付名（`hsq1_R2V版_30s/15s.mp4`），**旧版先改名归档**（`…_v15_30s.mp4`）再覆盖
- [ ] 飞书回显「视频: 0 success」= **成功**（不是失败）

## 3️⃣ 生成脚本的工具坑（本项目反复栽，每次白跑一轮）

- **submit_vN.py / build15_*.py / verify_*.py 一律用 `write_file` 直接写文件**，
  **不要用 shell heredoc（`python3 - <<'EOF'`）拼**：heredoc 里的 `\n` 转义会被毁，产出语法错误的脚本。
  本项目两次 `SyntaxError: EOL while scanning string literal`，另一次 `re.sub(BODY…)` 把字典截断只写了 4739 字节。
  改脚本时优先 `patch`（改一处）或 `write_file`（整份重写），**改完先 `python3 -c "import ast;ast.parse(open('x.py').read())"` 验语法再提交**。
- `terminal` 报 `cd: <某个不存在路径>: No such file or directory`（会话 cwd 失效、后续命令全部 exit 126）→
  **显式传 `workdir`** 即可恢复，不必重建会话。
- 含中文/空格的目录做 `ls`/`cp`/glob 时容易失配 → 改用 Python（`shutil.copy2` / `os.listdir`）。
- 后台长任务：一次提交多段后，用 `background=true` + `notify_on_complete=true` 跑 fetch 轮询脚本，
  不要在 foreground 里 sleep 等待。

## 4️⃣ 用户验收习惯（本项目已反复印证）

- 用户会**逐镜挑问题**，且**眼光很准**（"产品高度有点高了"→实测 2.56 vs 真机 1.93；"太长了"→2.45）。
  → 他指出的每一处，**先用像素/标尺确认数量级**，再改；不要凭感觉改措辞。
- 他也会**顺着标准追问下一处**（修完这一镜，下一镜同样的毛病他也看得见）→
  一次修完**顺手把同类镜一起过一遍**（同标准自查），比等他指出更省轮次。
- 反馈措辞往往很短（"尺寸不对 太长了""又是侧面充电"）→ 要**自己判定是"比例问题"还是"画面占比问题"**，
  必要时两者一起改（本项目结论：只改比例措辞压不住，"看着大"要靠画面占比硬指标 + 机位退中景）。
- 交付报告：**结论先行**（✅已交付 + 一句话证据 + ≤5 行表），细节留文档，不要把过程写成流水账。
