# 用户发截图说「这个镜头有问题」时怎么办（2026-09-17 建立）

## 触发场景
成片交付后，用户会**把成片截图发回来 + 一句话**，例如：
- 「这个镜头产品高度有点高了」
- 「水洗镜头产品顶部好像失真了」
- 「人物太呆滞，而且没有情景，单纯的罗列场景」
- 「视频里面不要体现价格」

他给的是**看图说话，没有时间码**。规则：**不要问他"第几秒"**，自己定位。

## 第一步：把用户截图定位回成片时间码
用户截图常带**手机黑边**且经过微信压缩。做法（脚本：`scripts/locate_reported_frame.py`）：
1. 截掉黑边：按 9:16 取图片中间区域（`th = w*16/9`，垂直居中裁）
2. 缩到 90×160 灰度，与成片**每 0.5 秒**抽的帧算 MSE
3. 最低 MSE 的帧即用户所指（实测：命中 MSE 6.6 / 次优 24.9，区分度足够）

## 第二步：2 倍放大 + 网格量化（不要凭整体观感下结论）
抽该帧 → crop 产品/人物区域 → ×1.7~2 + **40px 网格** → 交给视觉逐项问：
- **产品类**：数网格算**长:径比**（真机 1.93）、网面颜色/黑环宽度、Haier 次数与位置、侧面开孔、手指是否自然
- **人物类**：上唇有无胡须、眉毛皱不皱、下巴有无发绿/发青的胡须色块、是否同一人、浅蓝衬衫是否贯穿
- ⚠️ **颜色类判断必须看原始分辨率**：我在缩略拼图里把两版候选的下巴判成"发绿"✗，
  用户放大发回来后发现是干净的 —— 小图缩放会产生色偏。

## 第三步：按缺陷类型定返工范围
| 用户说法 | 真实含义 | 处理 |
|---|---|---|
| 「产品高度有点高了」 | 机身被拉长（实测 **2.56** vs 真机 1.9，拉长 35%） | 三条同时上：写「**短圆柱**、总长≈直径 **1.8** 倍、≈他手掌宽度」＋人体锚点「直径≈两根手指并拢」＋**换机位**（别竖举到脸前，改斜握胸前、机头朝斜上方） |
| 「顶部好像失真了」 | 产品小到 1/8 画面高时，机头糊成深色块 | 明确写「**机头朝上，黑色环带＋金黄色刀网清晰可辨、机身完整不糊**」＋给足尺寸（≥1/6 画面高，别缩到 1/10 以下） |
| 「人物太呆滞 / 单纯的罗列场景」 | 分镜只写了动作，没有动机与变化 | 每个镜头补**动作链＋动机＋表情变化**：如电梯镜「低头看手表 → 对不锈钢门板倒影理衬衫领口 → 抬头，眼神从疲惫转自信」 |
| 「不要体现价格」 | 价格经常变化 | 删 `overlay_cfg.json` 的 `price` 键（装配脚本会自动跳过）＋15s 脚本里的 `ov_price.png`；尺寸重量参数条可留 |

**返工范围**：改的是 prompt/分镜 → 重出**受影响的那一段**（10 秒 ≈ 6 元 / ≈13 分钟，三段可并行提交）；
其余段落不要重跑（会丢掉已经过检的细节）。

## 第四步：改完必须走完整复核，不能只看改动点
逐镜 2 倍放大过 5 项 → 装配 → 抽帧看花字/字幕/合规标是否落位 →
把成片音轨抽出来 STT 反查（确认台词没变）→ 飞书发送后回读消息列表确认送达。
