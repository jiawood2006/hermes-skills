# wan2.7 参考生视频（r2v）：锁产品 + 锁人物（2026-09-15 实测）

## 为什么需要它
t2v 生成的剧情片场景真实，但**产品是模型自己编的**（实测：给"迷你剃须刀"的文字，
出来一把通用款）。用户看到成片的第一句反馈是「场景很好，但产品不准确」。
解法不是改 prompt 措辞，而是**把我方真实商品图作为参考图传给 r2v**。

## ⚠️ 决策铁律（2026-09-16 白亏一轮换来，先读这条）
**只要用户诉求里有「不要贴图感」「产品要真的在场景里」→ 直接走 r2v 多参考图，别绕。**

被否定的两条路（都保得住产品细节，但过不了"真实感"这关）：
1. **官方图抠图 → 叠到 AI 背景上**（合成卡）。即使 alpha 修干净、加阴影加颗粒，
   用户一眼仍判「这种又成贴图了」（原话）。根因：产品像素不是场景渲染出来的，
   光影方向、透视、手部接触关系必然对不上 —— 修得再好也只是"更不容易被发现"。
2. **AI 出人/场景 + 产品卡贴片拼片**（时间轴分段拼）。同因被判贴图。

对照：r2v 的产品是模型**按参考图在场景里画出来的** —— 手持、贴脸、水流冲刷、插线充电、
塞进包里全部光影自洽，这正是用户要的。代价只是细节（蜂窝网孔纹理、logo 字母）
会有轻微漂移，**用户已明确接受**（原话：「代价：产品细节是AI画的，会轻微漂移」）。

r2v prompt 里必须写死的两条（不写就会漂）：
- 「顶部黑色环带内嵌**浅金色蜂窝编织网状**刀网（金色细密编织网孔，**绝对不是光滑实心金色圆盘**）」
- 「机身下部印有**完整清晰的 Haier 英文字母**（五个字母拼写正确、清晰可读，不能变形乱码）」

## 请求结构（实测可用）
```
POST https://dashscope.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis
Authorization: Bearer <DASHSCOPE_KEY>
Content-Type: application/json
X-DashScope-Async: enable
```
```json
{
  "model": "wan2.7-r2v",
  "input": {
    "prompt": "写实风格家庭短剧，竖屏手机拍摄质感，自然光，真实皮肤质感。图1是……（产品细节写全）……图2的年轻女性是女主角，请保持她的五官、发型、妆容与图2一致。第1个镜头[0-4秒]特写：……第2个镜头[4-10秒]中景：她举起图1的剃须刀对镜头说：“就这么点大，口袋一塞就走。”画面中不要出现任何文字、字幕、水印。",
    "media": [
      {"type": "reference_image", "url": "https://<公网>/hsq1_ref.jpg"},
      {"type": "reference_image", "url": "https://<公网>/hsq1_girl.jpg",
       "reference_voice": "https://<公网>/seg2.mp3"}
    ]
  },
  "parameters": {"resolution": "720P", "ratio": "9:16", "duration": 10,
                 "prompt_extend": false, "watermark": false}
}
```
轮询同 t2v：`GET /api/v1/tasks/<task_id>` → `output.video_url`；
`usage` 返回 `{duration, input_video_duration:0, output_video_duration:10, SR:720, ratio:"9:16"}`。

## 参数要点
| 项 | 值 | 备注 |
|---|---|---|
| `model` | `wan2.7-r2v` / `wan2.7-r2v-2026-06-12` / `wan2.6-r2v` / `wan2.6-r2v-flash` | 2.7 默认有声；2.6 需显式 `audio: true/false` |
| `parameters.ratio` | `9:16` / `16:9` | ⚠️ **不是 t2v 的 `size`**，写成 `720*1280` 会报 size not match |
| `parameters.resolution` | `720P` / `1080P` | 与 ratio 组合决定输出分辨率 |
| `parameters.duration` | 秒（实测 10 可用） | 计费按 duration |
| `prompt_extend` | `false` | 要精确控制台词/构图时关掉，否则被改写 |
| `watermark` | `false` | 平台水印文案固定"AI生成"；我方自己加合规标注更好控制 |
| `media[].type` | `reference_image` / `reference_video` / `first_frame` | 每张参考图只放一个主体 |
| `media[].reference_voice` | 公网 mp3 | 音色参考（不是 audio_url，r2v 无 audio_url）。⚠️**时长 ≤10 秒**，超了直接 `InvalidParameter: duration should be at most 10s` 秒拒（实测 12.384s 被拒，改 8.7s 通过） |

参考指代：中文 prompt 用「图1、图2」；英文用 `Image 1`；顺序与 media 数组一致。

## 价格与额度（北京，2026-09）
| 模型 | 720P | 1080P | 免费额度 |
|---|---|---|---|
| `wan2.7-r2v` | 0.6 元/秒 | 1 元/秒 | **50 秒（独立于 t2v 的 50 秒）** |
| `wan2.6-r2v` | 0.6 元/秒 | 1 元/秒 | 50 秒 |
| `wan2.6-r2v-flash` | 0.3 元/秒（无声 0.15） | 0.5 元/秒 | 50 秒 |

所以"先用 t2v 试水、再用 r2v 锁产品"两轮都可以不花钱。

## 参考图准备（踩过）
- 电商抠图常见 **rgba 透明通道 → r2v 不支持**，必须拍平转 JPG：
  `ffmpeg -y -i 正面图.png -vf "scale=1400:-1,format=rgb24" -q:v 2 hsq1_ref.jpg`
- 尺寸限制：宽高 240~8000px、宽高比 1:8~8:1、≤20MB
- 产品图选**干净正视图**（无文字/无贴图/无促销标），白色或纯色背景
- 托管：`scp xxx.jpg yunvela:/tmp/` → `sudo mv` 到 `/opt/yunvela-site/dh/` →
  `curl -s -o /dev/null -w '%{http_code}' https://yunvela.com/dh/xxx.jpg` 必须 200

## 角色一致性做法（跨段落同一演员）
1. 先用 t2v 出一版（或任一段成片），从里面抽帧找**清晰的角色正脸/半身**
2. `ffmpeg -y -ss 6.0 -i seg2.mp4 -frames:v 1 -q:v 2 frame.jpg`（⚠️ `-ss` 用片段内相对时间）
3. 裁成脸+肩，**尽量不带产品**（否则和产品参考图互相干扰）：
   `-vf "crop=440:600:140:60,scale=880:-1"`
4. 传 r2v 时作为第二个 `reference_image`，并把 `reference_voice` 指向该角色配音 mp3
5. 配角（阿姨/同事）不值得耗额度，交给 prompt 描述即可（实测配角用文字描述效果可接受）
6. 每个角色一张图 = 一条 media 项；"每张参考图仅一个主体"是硬约束

## 实测结果（HSQ1 剃须刀 · 2026-09-16 30s 正片 · 720P × 3 段）
- 产品在场景里全部自然成立 ✅：车厢里从储物格取出→手持特写→贴脸补剃→镜前侧脸→
  **水龙头下冲洗（Haier 标识完好，水流真实绕过机身）**→床头柜 Type-C 充电→塞进旅行包。
  **上一版被判"水洗时 haier 标识乱了"的问题在 r2v 下自动消失**（因为不再是贴图/重画叠加）。
- 3 段 ×10s 走 720P 免费额度 = **0 元**（r2v 有 50 秒独立免费额度）。
- 人声：模型按 prompt 引号里的台词**自带配音+口型**（无需再跑 videoretalk）。
- ⚠️ **必做 STT 反查**：3 段里 seg3 前 5 秒转写成乱码（「恩师温喜年 冲一冲 皆胜利冲」），
  后 5 秒才说对 → **乱码段必须重跑**（重跑时把该句单独放前、并加「台词只说一遍，不要重复」）。
- 轻微漂移（可接受）：网面偶尔退化成"光滑金色盘 + 放射纹"、logo 偶尔读作「Hsior」。
  加强上面那两条 prompt 可降低概率，但不保证 100%（AI 文字/纹理固有抖动）。
- 出片耗时：3 段并行 ≈ 6~8 分钟。

## 实测结果（HSQ1 剃须刀 · 第2段，2026-09-15）
- 生成片里机身 = **深灰圆柱 + 正面 Haier logo**，与参考图一致 ✅（t2v 版是模型自编的通用款）
- 人物与角色参考帧同一人 ✅
- 台词 STT 反查 = 我们写的："就这么点儿大，口袋一塞就走，8500转高速马达，配上旋转三叶刀片，硬胡茬也一遍过" ✅
- 未对齐项：**刀网颜色**（参考图金色 → 生成偏黑）→ prompt 补"刀网为浅金色/钛色金属网面（不能是黑色）"
- 出片耗时：2 张参考图 / 10 秒 / 720P ≈ 4~5 分钟（比 t2v 5 秒测试的 ~1 分钟长）

## 配音一致性：分段生成必查（2026-09-16 用户指出「配音要考虑好」）
分段生成时**模型每段随机给一个嗓音** —— 单看每段都正常，连起来就"像换了三个人"。
- **取证方法（可量化）**：抽各段音频算**基频中位数**（40ms 帧自相关 + 能量阈值），
  实测 HSQ1 三段 = 125 / 168 / 154 Hz，**段间差 23~35%** → 人耳必然听出不连贯。
- **修法**：给人物那张参考图的 media 项挂 `reference_voice`（我方 edge-tts 音色 mp3，≤10s），
  三段共用同一份 → 音色收敛。备用法：整片改用我方配音 + `videoretalk` 对口型（0.08 元/秒，1800s 免费）。
- **音色先定死再出片**：edge-tts 可选 `zh-CN-YunjianNeural`(云健 122Hz 低沉)、
  `zh-CN-YunyangNeural`(云扬 136Hz 专业播报)、`zh-CN-YunxiNeural`(云希 182Hz 年轻清亮)；
  用同样方法量基频 → 发样本给用户挑，别默认。
- 交付物发飞书：mp4 用 `msg_type=media` ✓；**mp3 用 `audio`/`media` 都报 400，只有 `file` 能发成功**
  （`feishu_send_media.py` 已按扩展名自动选型）。

## 多说话人段的坑（实测）
- **一段里有两个说话人时，只给一个 `reference_voice` → 另一人的台词会糊**（听不清/变含糊）。
  两端做法：①每人各给一份自己的音色 mp3；②或把该段改成单人台词，把对话拆到不同段。
- 判断方法：STT 反查该段音频，若某个说话人的句子转写乱码而另一人清楚，就是这个原因。
- 台词写进 prompt 引号里模型会照读，但**语音细节（情绪/清晰度）不受控** → 每段至少 STT 复核一次。

## ⚠️ 参考图必须覆盖"会被挑错的部位"（2026-09-17 实测根因）

用户指出「充电口画在机身正面」时，**根因不是 prompt 写得不够，而是参考图里没有那一面**：
我一直只喂正面产品图，而 Type-C 口在**底部端面** —— 模型没见过它，只能凭空编，编到正面去了。
改文案改了三轮都没用。

**修法**：把官方**底部视图**（`3.png`：底部端面=电源键同心环 + 下方 Type-C 插孔 + 指示灯）
裁成 JPG 当**第三张 `reference_image`（图3）**，prompt 补一句：
「图3=同一台机器的底部视图：底部端面中间是圆形电源键，下方是 Type-C 插孔，旁边一个指示灯；
机身正面与左右两侧没有任何接口或开孔。」
实测：**正面/侧面开孔归零 ✓，充电镜头接线落在底部端面 + 端面电源键与蓝灯齐备 ✓**。

→ 通用规则：**产品上任何一个"用户会挑错的部位"（接口 / 按键 / logo / 刀网纹理），
都必须有一张参考图能看见它**；看不见的部位，写多少文字约束都挡不住模型编。

## 交付前必查（2026-09-17 用户第 3 次指出同类问题后固化）

⚠️ **必须把每一镜的产品区裁出来放大 2 倍逐个核对，禁止只看小尺寸拼图。**
实测漏检：拼图每格仅 240~360px 时，**接口/logo 级错误根本看不见** —— 我"看着没问题"就交付了，
用户一眼指出「充电口画在机身正面」「水洗镜头尺寸偏大」「网面成银色梳齿、机身变矮胖罐」。

R2V 每镜独立生成 → 产品这 5 项**每镜都会重新漂**，交付前逐镜过一遍：

| 项 | 正确形态 | 模型常见错 |
|---|---|---|
| 充电口 | 只在**底部端面**（朝下那面） | 画到机身正面/侧面；底部多出一节带椭圆口的黑段 |
| Haier | **灰色机身正面下方，只印一次** | 印到黑色环/黑段上、上下各印一次、位置乱漂 |
| 外形 | **直筒圆柱**（长:径 ≈1.9:1），顶部黑环与机身**齐平同宽** | 收腰/台阶/锥形/矮胖罐（1.3:1）、黑环宽出一圈 |
| 刀网 | 浅金色**蜂窝编织网** | 银色梳齿、平滑金盘、放射状条纹 |
| 尺寸 | 产品长 ≈ **手掌宽的 0.9 倍**（握住时手掌能整个包住、五指合拢能绕过背面）；**粗细 ≈ 他两根手指并拢**（直径÷掌宽 ≤0.5，真机 0.46）；水洗/特写镜必须**中全景、产品占画面高 ≤1/8**，否则必然"看着大" | 偏大 1.2~1.5 倍（"拍成了保温杯"）；直径画粗 37% 变"胖杯子" |
| 眼镜（角色戴镜时） | 镜框**规整、左右对称、镜片不糊**；说话镜头过 videoretalk 后**要再核一遍** | 镜框塌陷/融进脸/单边缺失（AI 最易崩部件，缩略图看不出，必须 2 倍放大） |

这 5 条要**逐条写进 prompt 并带反面词**：「正面与左右两侧完全没有开孔」「只印一次」
「无收腰无台阶无锥形」「不是银色、不是梳齿、不是平滑圆盘」「底部没有多余的一节黑色段」。

放大核对做法：`ffmpeg -ss <t> -i seg.mp4 -frames:v 1 -vf "crop=<w>:<h>:<x>:<y>,scale=iw*2:-1"` 逐镜看图。

## 「看着大」的两个根因 + 两条修法（2026-09-17 用户第 4 次反馈后量化定案）

用户说「水洗的镜头还是有点大」时，**先量再改，别猜**。量化后发现是两件不同的事：

| 根因 | 实测 | 修法 |
|---|---|---|
| ① **直径胖**（不是长度长） | v7 水洗：长÷掌宽=0.91 ✓达标，但**直径÷掌宽=0.63**（真机 0.46）→ 长:径只有 1.45（真机 1.9）→ 看着像"胖杯子" | 锚点改成 **「粗细≈他两根手指并拢的宽度」**（39mm≈2×19mm）+「长:径≈1.9」+「绝不是保温杯/易拉罐/咖啡杯」 |
| ② **构图太近** | 说明写「中景/产品很小」模型也照样怼特写（水洗动作天然吸引模型聚焦产品） | 明写 **「产品长度不到画面高度的八分之一」** + 「能看到他的上半身、水龙头、洗手台」→ 实测产品降到**画面高度 1/22** ✓ |

**最有效的一招：加第 4 张参考图当"粗细视觉锚点"。**
把官方实拍（拉页真人图）里**「真手握产品」的局部**裁出来
（`crop` 掉人脸，只要手+机身；避开画面上原有文字），作为 `reference_image` 传进去，
prompt 写：「图4=官方实拍里真手握产品的局部，**只用来参照产品粗细**（粗细≈他手指宽 1.5 倍）；
**不要抄图4的色调/背景/服装/构图**」。
→ 实测：文字锚点三轮压不住的"胖"，加这张后同段产品比例正常（长:径≈2.0）。

**③ 机位比文字更管用**：手持特写必须**从侧面拍**（画面里能看到整根机身的完整长度）。
同一个 prompt 下实测：**正面/仰角机位 → 机身被压成"矮胖罐"（长:径 1.28）**；
改成「镜头从侧面拍他的手，能看到整根机身的完整长度」后回到 1.9~2.4 ✓。
→ 凡是要展示"产品本体"的镜头，先想机位，再改文字；正面机位是"看着大/看着胖"的隐形元凶。

## 换男主角（换角）标准流程（2026-09-17 实测）

用户说「男主角形象有点凶，能不能换一个」时，**不要自己拍板选脸**，先生成候选让他挑：

1. **生成 4 个不同气质的候选**（走 DashScope 标准端点
   `POST /api/v1/services/aigc/multimodal-generation/generation`，`model=wan2.6-t2i`）；
   统一写死「**不要皱眉、不要浓眉怒目、眼神温和亲切**」，只变年龄/职业/穿着
   （温和商务40 / 亲切邻家40 / 阳光年轻28 / 儒雅斯文50）。
2. **拼成一张 4 格带标签的图，发飞书**给用户挑（↔ 别只发文字描述）。实测他直接回「阳光年轻的样子最好」。
2b. **用户也会自己发参考图**（如豆包生成的 AI 形象：「像这种」）。此时不要再生成候选 ——
   直接把他发的那张当角色参考图：①裁掉右下角平台水印（「豆包AI生成」）和画面边缘的镜框/虚影
   ②裁到「脸＋肩＋服装」使服装信息一起带进去 ③`scp` 到公网并 `curl -I` 验 200 ④作为 `reference_image` 传。
   **换装后所有含袖口/衣着的段落都要一起重出**（西装 ↔ 衬衫不能混）。
3. 选中的那张 → **传到公网**（`/opt/yunvela-site/dh/char_man_c.jpg`，`curl -I` 验 200）
   → 替换 prompt 里的「图2=男主角」描述（写全**年龄/发型/笑容/服装**）。
4. **服装要贯穿全部镜头**：换角后旧段落的服装会和新男主撞不上 ——
   水洗/充电等**没有人脸但有手和袖口**的段落必须一起重出（实测：旧段深色西装袖 ↔ 新男主浅蓝衬衫 → 不同步就是穿帮）。
   重出时在 prompt 里写「浅蓝色衬衫（袖子挽到手肘）配深色西裤」。

## 🔴 人物「太假」正解：抄样片拍法，不是换模型（2026-09-17）
用户发来样片说「人物不真实。太假」。拆样片（**只有 544×960**，比我们 720P 还低）→ 它真在**拍法**，不在分辨率/模型：
1. **旁白＋生活抓拍**：样片全程没人对着镜头念台词（音频是画外旁白）→ **去掉对口型**就干掉最大假感来源（还省掉 videoretalk 一步）。
2. **暖色实用光/侧逆光**：台灯、窗光当光源，有明暗过渡和真实阴影；**影棚平光 = 假**。
3. **真实皮肤**：法令纹/眼袋/毛孔/肤色不均/真实牙齿；**磨皮＋过度对称 = 假**。
   ⚠️ 只写「淡胡渣」会被画成**络腮胡/八字胡** ✗ → 必须补「**上唇绝对没有胡须、没有八字胡、没有络腮胡**」。
4. **有生活痕迹的空间＋浅景深**：台灯/相框/水杯/纸巾等道具，别用空背景。
5. **抓拍式表情**（笑到眯眼、低头微笑），不是摆拍微笑。
6. 每个镜头在 prompt 里**显式写地点**（"仍在车内驾驶座"），否则模型会自己换场景（实测：车内镜→卧室镜）。

**写实版候选人流程**：`wan2.6-t2i` 出 4 个候选，统一约束「真实摄影不是影棚模特照／实用光有方向／真实皮肤可见毛孔胡渣／背景生活道具／抓拍表情」，
只变年龄职业 → 拼 4 格图发飞书挑。实测 4 张真实度均 9/10+（此前影棚风版本只有 6/10）。

## 旁白轨（VO）制作
- 整片一条 30s 旁白 = 每条台词单独 edge-tts → `adelay=<起点ms>` + `amix=inputs=N:normalize=0` 落位，**台词起点对齐字幕起点**（见 `overlay_cfg.json`）。
- 脚本 `/tmp/r2v/build_vo30.py <voice> <rate> <out>`（云希=年轻自然 168Hz；云扬=成熟播报 129Hz）。
- ⚠️ edge-tts **连续多句会被节流失败** → 必须重试循环（≤6 次、间隔 4s）。
- 装配时**直接铺整条 VO 轨**（各段自带音频全丢弃）；15s 版 = VO 的 0-10s ＋ 20.1-25.07s 切片。

## ⚠️⚠️ 三条硬规律（2026-09-17 v16→v17 实测，加情景后产品会退化）
给 prompt 加生活情景（用户要求「不要只罗列场景」）之后，**产品会退化**，实测三条：
1. **prompt 变长会稀释产品锁** → 同一套产品措辞，v15 金网正确、v16 加了情景文字后金网变浅金/银白、
   长径比从 2.03 掉到 1.58。**修法：在产品锁后面（prompt 尾部）再写一段「【再次强调·最高优先级】产品必须与图1图2完全一致……任何一帧都不许变形变色变胖拉长」** —— 尾部指令权重高。加情景 ⇒ 必须加尾部重申。
2. **俯拍会把机身压短** → 手持特写里镜头从上往下看，机身被透视压缩，长径比 1.58 ✗。
   **修法：写「镜头与产品齐平、从侧面稍低处拍（不要俯拍）」**，与「产品不占满画面」一起写。
3. **「没有人直视镜头」要显式写** → 不写的话模型会让主角盯着镜头，观众看到的就是「摆拍/呆滞」。
   正解：「**全程没有人直视镜头**，视线落在手里的机器、镜子里的自己或环境上」（对齐用户样片的抓拍感）。
- 长径比措辞实测敏感区间：写「细长…约直径2倍」→ 2.03~2.56（偏长）；写「短圆柱 1.8倍」→ 1.5~1.7（偏胖）。
  真机 1.93 ⇒ 用「上下等粗的**直筒**圆柱、总长≈直径**1.85**倍」＋手掌锚点，并靠**机位**（齐平/侧面）兜住。

## ⚠️⚠️ 「产品显得太大」是最高频投诉 —— 比比例更常见（2026-09-17 用户三次）
用户原话累计：「这个镜头产品高度有点高了」「水洗的镜头还是有点大」「**尺寸不对 太长了**」——**都是"这台机器在画面里显得太大/太长"**。
只改长径比措辞（v16/v18 试过两轮）**压不住**，必须两条一起上：

1. **【尺寸锚·写死】「这是一台 70 毫米长的迷你剃须刀，比成年人的手掌还短。产品出现在画面里时必须显得很小：
   整台机器的长度不超过画面高度的六分之一（特写镜不超过四分之一）；绝不许拍成保温杯、易拉罐、大水杯那么大的东西。」**
   —— 把产品在**画面里的占比**当硬指标写进 prompt，比写长径比有效。**改完要用标尺量画面占比验收**（v19 实测 20% ✓）。
2. **【机位】退成中景**：让画面里出现主角上半身/环境，机位与产品齐平、别让手和机器贴镜头（凑近就显得大）。
   v19 把「镜前手持」从"机器顶到脸前"改成"中景＋机器拿在胸前"，占比立刻从 ~48% 掉到 ~20% ✓。
