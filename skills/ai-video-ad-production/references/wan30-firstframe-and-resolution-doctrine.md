# wan3.0-video 的两条系统级发现（2026-09-18 实测）

## 一、⚠️ 参考图1 会被当成「画面首帧」

**症状**：三条不同钩子的开场 0.8 秒**长得一模一样** —— 全是同一张金网刀网微距。
**根因**：`wan3.0-video` 用 `input.images`（多参考图）时，**把参考图1 当作画面首帧**。
我们把图1 设成"刀网微距（金色校准）"，于是每条片都从那张微距起步。
**修法**：要"开场就是他本人"→ **把图1 换成男主图**
（代价：少一个金色校准锚点，刀网金色有变浅风险，换完必须重核刀网）。
**核验要求**：抽帧核验**必须含首帧（0.2~0.5s）**
—— 只看中后段会完全漏掉这类系统性问题（本项目连续两轮都漏了，直到对比"为什么三条开场一样"才发现）。

## 二、⚠️ 原生 1080P 不是升级，是重抽卡

用户问"测试阶段用 720P 省钱，定稿之后改 1080P 可以吗" → 同 prompt / 同 5 张参考图 / 5s 直接对照：

| | 720P 生成 → 装配升 1080（现做法） | 原生 1080P |
|---|---|---|
| 产品形态 | ✅ 等粗直筒、比例正 | ✗ 机头歪斜变形、几何不对 |
| 刀网 | ✅ 饱和香槟金 + 放射网格 + 宽黑环 | ✗ 2.0s 帧变暗灰黑圆盘，金丢了 |
| logo | ✅ 干净 | ✗ 位置漂移、偏软 |
| 锐度 | ✅ 干净利落 | ✗ 并不更锐，反而更"塑料" |
| 文件 | 5.7MB | 14.4MB（×2.5，画质没提升）|
| 构图 | — | ✗ **整条是另一条片**（机位景别全变）|

**结论（已定，不再重议）**：
- **生成一律 720P**；成片由装配器升到 **1080×1920**
  （字幕/花字/参数条/CTA 本来就在 1080 画布上渲染，`scale=1080:1920`，0 成本）。
- 产品特写要清晰，正解是**官方真像素图做动效**（原生清晰 + 100% 保真 + 几乎 0 成本），
  不是花 1.8 倍钱把整片 1080P 重跑一遍。
- 平台侧：抖音/快手竖屏会二次压缩，720→1080 在手机信息流里几乎看不出差别；
  观感来自光照、产品清晰度、字幕锐利度，不是分辨率数字。

## 三、尺寸措辞的反向坑（同轮发现）

正文里写"这台机器很小 / 长度不超过画面高度的六分之一"
会把模型**往小里压** —— 这是用户反馈"**产品太小**"的**文本根因**。
→ 删掉这类倒向小的措辞，只留**正向下限**：
*机身总长 ≈ 他手掌长的 1.1~1.3 倍、约占画面高度的 1/6、刀网黑环与金色网面清晰可辨*。

## 四、引擎切换（make_ad.py 已支持）

项目 JSON 里写 `"model": "wan3.0-video"` 即切换；字段差异：
- `wan3.0-video` → `input.images`（URL 列表）+ `parameters.watermark=false`
- `wan2.7-r2v` → `input.media:[{"type":"reference_image","url":...}]`

一次提交只能一个 duration → 5s 与 10s 的段要拆成两个项目（两个 runid）分别提交。
